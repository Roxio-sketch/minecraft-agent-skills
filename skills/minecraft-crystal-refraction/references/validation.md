# 验证与复跑

## 制作台

在 skill 根目录运行 `python scripts/serve_preview.py --port 8771`。无外部字体、图片或服务，仅绑定 127.0.0.1。端口被占用时换端口，不停止无关进程。选择已有 Python；本机运行时的绝对路径不作为技能前提。

也可指定 `--port 0` 自动获得空闲端口，使用终端实际打印的地址；Windows 服务采用独占绑定，避免相同端口落到另一个制作台。

自动验证需要 Node.js、Playwright 和浏览器：

```powershell
node scripts/validate_preview.cjs --url http://127.0.0.1:8771 --out <证据目录> --browser <浏览器可执行文件>
```

省略 `--browser` 时使用 Playwright 已安装的 Chromium；不要为运行脚本自动安装大型浏览器。环境缺失时报告限制并保留可人工打开的制作台。输出为数值检查 JSON、配方、三套大图与 16/32 小图以及界面截图；证据放在工作目录而不是安装 skill 内。

脚本检查可观察行为：固定状态复现、零效果保留原图、n=1 无色散还原、无色折射、独立色散、动画开关、固定晶片、seed、遮罩外不变、视角变化、柔化、三配方小图、导入导出、无效配方拒绝与主要 UI 控件。每次捕获检查 GL error；其通过不证明设计美感或性能。

状态回归另运行 `node scripts/validate_state.cjs --url <本地地址> --out <证据目录> --browser <浏览器路径>`。检查 amount=0.4/0/1 的原图往返、配方保持与大/小图像素、导入/预设退出对照、时间跨越/到达上限自动暂停、上限配方导回及重置后播放。测试使用独立页面，不改变用户已打开页面的设计。

查看图片时至少比较：无色折射确实位移背景；色散沿晶片差异产生而非整屏统一偏移；窄窗口读得到大面关系；边缘没有把整张图抹白；小图是否仍可辨别主体；屏幕边界 clamp 痕迹是否可接受。证据中注明演示采用固定星域和非物理显示颜色。

## 资源生成

运行 build_shader.py，检查生成三件套与 uniform 契约。用当前可用的桌面 GLSL 编译器验证 150 源；若只做 ES host 变体编译，明确记录变更后的版本和顶点输入，不称桌面编译通过。不要为了制造绿灯修改测试去忽略 shader 错误。

## 真正进入 Minecraft 后

记录确切 MC/Forge/Java/GPU/驱动及资源包。检查 GUI、左右手、掉落物、展示框、目标模型 overrides、自定义 renderer 入口和 glint。只有覆盖到的类别才标为支持。

世界折射额外检查：地形前后遮挡、相机在效果内外、屏幕边缘、近裁面、FOV/GUI scale、窗口变化、相邻透明体、两个折射体重叠、水/粒子、资源重载、异常恢复和退出世界。用“效果关闭→开启→关闭”的固定场景对照排查残留状态。

性能测基础模型、无色折射、RGB 色散和柔化各自的 CPU/GPU 增量；记录分辨率、覆盖面积、实例数量、复制纹理成本、draw 次数与采样档。静态循环上限不是性能基准。

交付时标注证据层级：静态参考 / 原创 GPU 预览 / 桌面 shader 编译 / 目标游戏实测。本轮没有游戏证据，不能沿用别的 skill 的 Forge 通过记录。
