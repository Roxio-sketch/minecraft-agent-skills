# 描述如何落实为材质

这里的范围值是创作起点，不是普适物理常数。先按空间和构图选方案，再调参数。示例 JSON 存在于工作台自己的 [recipes.json](../assets/authoring-lab/recipes.json)，不属于 Minecraft 已注册的配置格式。

## 三个可运行练习

三者共享原创有限薄层内核，可在 [制作台](authoring-workbench.md) 调整。它们改变了密度、遮挡、空间尺度、动态和颜色，不只换色。

| 练习 | 制作意图 | 关键参数起点 | 看什么 |
|---|---|---|---|
| 深空星海 | 暗背景、薄云、稀疏近星 | cloud 0.32、dust 0.8、density 0.72、depth 4 | 黑暗空间是否仍存在，星点是否有主次 |
| 紫蓝星云 | 云带为主体，亮部偏冰蓝 | cloud 1.55、dust 0.65、density 0.58、scale 0.8 | 气体是否成带，暗尘是否切开亮部，星点是否抢主体 |
| 赤金裂隙 | 暗尘更强，暖色光穿过间隙 | cloud 1.2、dust 1.5、density 0.43、depth 4.5 | 暗部是否压得太死，裂隙与星点能否分辨 |

当前预览仍是少量星层与简化发射/吸收，不包含多次散射、真实引力偏折、模型边缘折射或外扩 bloom。三个练习不是对 ArcaneVortex 材质的重制。

## 从措辞到制作动作

| 用户表达 | 优先动作 | 不应直接做的替代 |
|---|---|---|
| 更深、更空旷 | 降低底场/云覆盖，拉开前后亮度与尺度，检查视差 | 全部变黑，或仅提高迭代次数 |
| 更像无尽 | 保留方向场与星体分层的视觉机制 | 擅自改成体积烟雾 |
| 星云更厚 | 提高局部密度与遮挡，保持空区 | 给整个屏幕加亮色滤镜 |
| 星星更多但别嘈杂 | 增加远星数量，限制高亮大星的比例 | 每一层同样加亮加粗 |
| 近处几颗亮星 | 增加少量有位置/尺度控制的主星 | 全局曝光拉满 |
| 星点在内部移动、闪烁 | 独立调 starSpeed、twinkle、twinkleRate，先关闭云/尘检查位移，再固定位置检查明暗 | 仅加快星云或不断更换 seed |
| 缓慢、沉静 | 分别降低 speed 与 starSpeed，降低 twinkleRate，按需减弱 twinkle | 让整个星图同步明灭 |
| 流向裂隙中心 | 新增收敛/旋转速度场，保留稳定身份 | UV 匀速向一个方向滚动 |
| 看得到内部体积 | 明确原点、深度、透射率和遮挡 | 仅加随机旋转的二维层 |
| 符文永远正立 | 独立符文层，约束旋转/翻转，确认观察空间 | 沿用所有星体随机翻转 |
| 六个面连续 | 统一三维采样空间 | 每面单独铺同张方图 |

## 改结构而非只改参数的设计

### 分形无尽空间（方案，尚未加入工作台）

描述：“像方块里藏着无限延伸的星海，细小结构里还有更小结构，转头会展开。”

选择射线步进中的折叠/反演场，参考 [ArcaneVortex 的 star_sky 分析](arcanevortex-study.md)。可分出稳定的远层、少量高亮细结构和受控慢移的观察路径。迭代次数、步长、距离衰减与颜色权重分开；对小分母限幅，避免 NaN/Inf。先用少量步数与较低迭代研究视觉，再测质量档。不能使用现有 cloud 参数就宣称完成此结构。

### 黑洞与吸积盘（方案，尚未加入工作台）

描述：“黑色核心周围是一圈金色盘，后面的星空像被拉弯。”

先确定核心在窗口内的位置和角尺寸，再做盘的倾角、前后遮挡、内外亮度及流速；背景星域只承担对照。若真的要星光偏折，增加方向扭曲或弯曲射线，并说明是美术近似还是特定物理模型。一个旋转彩环没有实现星光偏折。

### 符文星域（方案，可复用旧 sprite 路线）

描述：“深蓝空间内漂着金色文字，层次丰富但文字能看清。”

用明确轮廓的字形 atlas，选择红通道亮度或 RGBA 契约后统一采样。主字形少且较大，远层以点与碎符号代替；限制翻转，减少运动模糊。多 mip 下留足图集边距，不把模糊过的字符当作细节。

## 一段可直接使用的用户描述

“使用 $minecraft-cosmic-material。目标 Forge 1.20.1 的这把剑：只覆盖剑刃内部，握柄和金属外缘保留。内部是深紫蓝星海，一条断续的冰蓝云带穿过中段，暗尘切开云带，近处有少量亮星。转动时能读出前后层次，动画很慢。先给固定时间、两个视角以及真实小图的对比，再接入游戏验证。”

这是一种表达方式，不是用户必须填写的问卷。实际用户只给一句话也应先生成可审查初稿。
