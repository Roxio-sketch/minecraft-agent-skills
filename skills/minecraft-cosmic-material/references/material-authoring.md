# 内部星空的制作方法

适用：用户用自然语言描述物品内部的宇宙、星云、空间裂隙或分形星海，希望得到实际材质。目标是从描述选算法、组织层次、制作资源并验收，不是给已有 shader 随意改一个颜色。

## 先决定内部究竟是什么空间

| 用户意图 | 合适的基本结构 | 真正提供的深度线索 |
|---|---|---|
| 像无尽装备，表面后面是遥远星空 | 多层方向场、稀疏星体 sprite | 方向随观察变化；各层尺度、亮度与旋转不同，不等于有限距离视差 |
| 星云封在剑里，近星和远星错开 | 局部有限深度的星点层 + 3D 密度场 | 平移观察点改变采样位置，前景透射率影响后方发光 |
| 内部无限延伸、万花筒或分形宇宙 | 折叠/反演程序场 + 沿射线累计 | 高频分形结构、距离衰减、路径运动；不是均匀星点的另一种 palette |
| 发光云团有边界，能走近/进入 | 包围体求交 + 体积积分 | 入射/出射边界、内部密度、遮挡、场景深度截断 |
| 一个黑洞或旋涡是主体 | 中心构图 + 极坐标流场/盘面 + 背景星域 | 明确焦点、环/盘的倾斜和遮挡；有引力偏折需求时才实现弯曲射线 |

Avaritia 路线见 [algorithm.md](algorithm.md)。ArcaneVortex 提供后三类的研究线索，见 [arcanevortex-study.md](arcanevortex-study.md)。选择不同结构时需要更换核心函数，不要把所有设计都归结为“噪声加星点”。

## 把描述转成一张制作单

不要求用户知道任何 uniform 名称。先按描述写清下面六件事；缺少的选择用符合主题的初稿补足，只有会改变结构的歧义才提问。

1. **空间隐喻**：遥远天幕、封存空间、分形空间、有限云体，还是中心天体？
2. **大形与主次**：横带/斜带/漩涡/团块/裂隙；焦点在哪里；哪里保留黑暗？
3. **发光层与遮挡层**：背景、远星、气体、暗尘、近星、主天体；各自颜色与强度。
4. **视角响应**：固定 time 后，转头、转物品、平移观察点各应该发生什么？
5. **动态节奏**：云漂移、整体旋转、星点微闪、偶发事件分别多快；哪些必须静止？
6. **载体与尺度**：哪些部位是窗口，保留什么实体边框；16/32 px 图标和手持近景各要读到什么？

示例解释：“很深的紫蓝宇宙，中央有断续云带，近处少量亮星，转动时前后错开，缓慢流动，保留金属边。”

- 选局部有限空间；画一条有暗尘切口的主云带，空区维持低亮度。
- 远星小且弱，近星少且有亮核，最多少量星芒；不是每颗星都扩大。
- 云的暗部偏紫、密集亮部偏冰蓝；亮度与色相分开控制。
- 冻结时间后移动观察点验证视差；继续时间但不移动相机验证云流动，两者不能互相冒充。
- 覆盖率使用材质区域 mask；外轮廓 alpha 仍来自原模型纹理。
- Forge 基线缺少对应字段时实现参数传递，不能只给物品写一段无人读取的 NBT。

## 制作顺序：先大形，再细节

### 底场与负空间

先关闭星点，只做底场与主体轮廓。背景不是一块提亮的蓝色；留黑让亮星和云体有参照。深邃感可以由暗背景、密度差与遮挡共同实现，不靠把全部层数翻倍。

构图包络先于细噪声：主云带使用一条弯曲带状权重，团块使用椭球权重，裂隙使用窄带与断裂权重，旋涡使用有中心和旋臂的权重。然后用噪声改变边界和密度。均匀 fBm 很容易变成铺满表面的彩色烟雾。

### 星点与星芒

- 使用稳定的 cell/seed 决定位置、大小、色温与亮度。不要让时间进入随机种子而逐帧重排星图。
- 区分数量、半径与亮度：增加数量不应自动放大星点；放大半径要检查总能量与重叠。
- 亮核、柔和晕和十字星芒是不同形状。远星主要是小亮核；星芒留给少数主亮星。
- 做球面映射时处理经度接缝和极区拥挤；做网格时检查邻格星体，避免亮晕被 cell 边界切断。
- 素材路线：旧 Avaritia 使用红通道强度，黑底灰白形状；不是通用的 RGBA 彩色贴花。需要彩色星体时修改采样/合成契约。mask 与星体素材是两种资源。
- 程序路线：在几何内算核/晕函数，不需要为每种配色生成新 PNG；语义明确的符文/天体剪影才更适合纹理。

### 星云与暗尘

建议拆为 `compositionEnvelope × shapedNoise`。低频决定大体积，中频决定褶皱，少量高频提供边缘纹理。先调低频，之后才增加 octave；增加频率不等于增加纵深。

域扭曲是先扭动采样坐标再采样密度，例如 `density(p + warp(p))`；不是给已算好的颜色叠一层相同噪声。扭曲幅度过大容易破坏云带主形，时间频率过高则像沸腾水面。

暗尘影响透射率：把它放在某个深度后，衰减其后方星云和星点。直接向最终 RGB 加黑色没有作用；最后统一乘暗色也不能区分前后。

### 深度合成

对于常密度的一小段长度 `ds`，可用以下近似组织发射与吸收：

```text
alpha = 1 - exp(-sigma * ds)
C += T * emission * (sigma > epsilon ? alpha / sigma : ds)
T *= 1 - alpha
```

`sigma` 是消光系数，`emission` 是单位长度发射系数，`T` 是到当前样本的透射率。这里省略复杂散射；不能称为完整的物理星云模拟。星点层按所在深度插入当前 `T * starRadiance`，不要先积分整团雾再把所有星点叠在最上面。

采样次数变化时同步改变 `ds`。若每步直接加固定 alpha，调质量档会同时改变不透明度。需要提前结束时依据透射率/边界，不把固定最大步数误当作物体大小。

体积渲染的公式依据可查 NVIDIA GPU Gems 第 39 章（前后顺序、步长与不透明度修正）和 PBRT Transmittance（指数透射率）；本技能给出的是任务内的简化实现，不复制完整章节。

### 色彩与发光

为底场、云暗部、云亮部和星点分别选色，先确认明暗结构。用密度/温度/距离去选择 palette，而不是最后把整张画面乘同一个颜色。

在选定的线性空间累计辐射值，最后统一曝光和显示转换。已有 framebuffer 或 shader pack 有自己的转换时，不再重复 gamma/tone mapping。工作台的曝光是演示显示管线，不可原样附加到任意 Forge framebuffer。

以下三者分开：材质不受环境光变暗、屏幕上的亮核/晕、对周围场景的真实照明。程序星晕不等于 bloom；Halo 不自动变成物品内部光照。

## 空间契约：移植物品时最容易出错的部分

方向式天空只需要方向，物品内部的有限空间还需要观察原点。把归一化方向循环采样很多次，不代表它已经锚定在物体内部。

- **局部有限空间**：逆模型矩阵把相机点和入射点转到同一个材质空间，再求射线。方向变换使用 w=0；点使用 w=1。相机已经在 view-space 原点时，不能再机械加一次世界 cameraPos。
- **缩放**：给虚拟长度定义单位；非均匀缩放后决定密度按世界长度还是局部长度解释。归一化方向后要相应换算行进距离。
- **多面连续性**：用统一的物体空间场穿过各面；每个面各用自己的 0–1 UV 会在棱边变成六张不同图。
- **平面物品**：可以定义表面后的虚拟薄层，不要求真实模型有厚度。它是美术空间，不应被宣称为真实几何内部。
- **GUI**：定义稳定的虚拟相机与构图尺度；不要直接照搬全屏 `gl_FragCoord / screenSize`，否则换格子位置会换图案。
- **世界场景体积**：需要当前场景深度与色彩副本、同单位深度比较及正确写回。这比单 pass 物品材质多一套接入，不是直接加两个 sampler。

## 缩小后的质量

`fwidth`/屏幕导数可估计采样足迹；在非一致分支、discard 或循环早退前取得所需导数。亚像素星核应过滤或简化，不应通过夸大随机闪烁补偿消失。

在 16/32 px 下检查轮廓、主云带和至少一种明暗层次。很多远星消失是有限像素的实际结果：可选更低频的 GUI 图案、少量保留的主亮星，或专门的图标质量档，但明确记录它与手持材质的差异。

为窄剑刃和大面积方块分别设构图，不假定方形预览的焦点必然落在剑刃 mask 里。调整顺序：窗口内大形 → 明暗与色彩 → 近星识别度 → 高频细节 → 动态。

## 一次设计的验收

- 同一 seed、time、view 下对比改前改后；记录改变了哪一个视觉关系。
- 关闭星点只看云与暗区；关闭云只看星点等级；改变暗尘时验证后景衰减。
- 冻结 time 转视角；固定视角推进 time；速度全部为零时画面应保持稳定，量化差异需标注。
- 真正以小分辨率重渲染图标，不能只缩放一张高分辨率截图。
- 当前实现能做什么、缺什么接口、新效果在什么环境通过，都记录清楚。编译检查不替代画面审查，预览不继承旧 Forge 样本的认证。
