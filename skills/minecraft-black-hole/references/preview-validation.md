# 预览、配方与验收

当前工作台为 v3.2，默认是 BlackHole 研究风格的体积尘埃，另有可直接观察核心、盘面、三层光晕、粒子与背景渐变的四个主配方。支持可调光圈、16:10 / 16:9 / 1:1 画幅、宽背景与背景透镜混合、盘面/背景/射线诊断，以及线性 HDR 后处理。具体调参与新增字段见 [v3.2 工作台](v3-workbench.md)。下文保留 v2.2 与更早的回归方法和历史证据；旧结果不证明新增画面的风格验收。

## 运行和操作

v2.2 历史记录：当时修正长时间剪切、重做极坐标光带、增加背景选择及足迹过滤，使用加长路径和新风格 2x2 超采样，默认关闭额外 sprite 和柔光。这些 v2 组合能力在 v3.2 中保留为可选配方。

在本 skill 目录执行 `python scripts/serve_preview.py --port 8771`。仅绑定 127.0.0.1、仅服务 assets/preview；打开输出的地址。Windows 使用 SO_EXCLUSIVEADDRUSE 且关闭地址/端口复用，占用时明确失败；`--port 0` 自动选空闲端口并打印实际地址。换端口无需修改 shader。Python 不在 PATH 时定位已有解释器，不默认安装新环境。用 Ctrl+C 停止。

旧 v2 制作台曾默认展示颗粒盘、独立螺旋粒子和三层光晕的完整组合；当前可从“颗粒吸积 · 完整组合”配方选择。配方列表已经按盘面算法合并，尺寸或配色相近的旧变体不再重复占用选择器；颜色、渐变、光圈和盘面细丝由控件调整。核心、盘面两端、粒子两端各有独立选色；粒子数量/速度/尺寸/补给半径/亮度和光晕总量/内缘/盘侧/外围均可调。支持拖动观察、滚轮视距、时间暂停/播放、质量档、剑刃示意、PNG 导出和 JSON 导入/导出。16/32 px 使用各自小 framebuffer 重渲染。

`black-hole.glsl` 是内核，`preview.js` 管理配方/渲染，`layers.js` 接入颗粒盘、光晕、可选双极喷流及独立 GPU 粒子；Forge 世界/粒子模板使用同版本内核；物品/面板仍保留旧场，背景/后处理/粒子颜色存在明确宿主差异。WebGL 粒子出生盘半径随 uOuter 调整，并在接近暗核前淡出，避免粒子四边形解析成粗糙的点环。临界盘的薄盘交点与掠射采样有独立预算；颗粒风格还会压低最接近捕获轮廓的前景累积，保留可读盘面并隐藏锯齿细线。选择器只展示四个主算法起点：体积尘埃、Unity 层叠光带、程序光带和颗粒吸积；电影宽带、全域渐变和经典条带仍保留在 `recipes.json` 作为旧 URL/导入的隐藏兼容变体。旧的同质色彩变体由颜色/渐变控件覆盖。导出 schema 为 `black-hole-preview/v2`，接受 v1；旧配方缺省使用经典条带、粒子关闭、halo=0、星点背景。导出后通过 /blackhole import 显式应用支持字段，接入读 forge-integration.md；相机/第三人称/地面问题使用 world-regression.md 的实际像素验收。

默认静止在 1.7 秒；播放时以秒推进，达到 100000 秒自动暂停，不能继续越界。未知字段明确拒绝，错误消息不会被动画帧清掉。导入后的视角恢复基准来自导入数据，选择器显示自定义名称；切换回预设会重新建立基准。工作台限制刷新频率以便交互，这不是 GPU 性能基准。预览不包含真实物品几何、世界深度、阴影、Minecraft alpha/光照和多 mod 干扰。

v3.2 的每个 canvas 先在独立 RGBA16F 缓冲中绘制盘/光晕与 additive 粒子，再做亮度提取、模糊、曝光、ACES 映射并复制到可见画布；射线状态诊断仍直接写入 RGBA8 结果。相同参数/时间/尺寸/诊断模式复用像素；speed 与 infallSpeed 为 0 且粒子关闭或速度为 0 时固定 GPU 时间。粒子使用同一核心/盘遮挡积分和剑刃 mask，程序星空不提供 Minecraft 地形深度。静止验收不等于跨驱动逐像素确定。

捕获或不透光射线在背景采样之前结束合成，避免零透射率乘上无效星云样本；HDR 源的 alpha 标记暗核，后期柔光不会把背景云光重新散射进事件视界。前方盘面和喷流已积累的源光仍保留。修改此链路时，用强星云、柔光与喷流组合，比较 `skyStrength=0` 和最大值在射线诊断确认的核心内部像素，预期 RGB 完全相同；同时看彩色原图，确认近侧盘未被粗暴遮掉。运行 `node scripts/validate_core_occlusion.cjs --url <预览地址> --browser <浏览器路径> --output <证据目录>`；本地证据保存在 `research/black-hole/core-occlusion-20261004/validation`。

## 自动检查

v3.2 渐变回归：`node scripts/validate_gradients.cjs --url <地址> --browser <浏览器路径> --output <证据目录>`。脚本隔离光圈半径/宽度/锐度、三层光晕独立渐变、核心边缘、盘面中段、粒子中段和大画幅背景近远配色；确认关闭新渐变时颜色变动不会污染旧视觉。它另检查 277.85 秒、100000 秒、旧配方缺省、未知字段和 WebGL 错误，并保存彩色大图与单层光圈截图。测试只证明所取配方/环境下的变化和回归，最终仍要看原图。

v2.2 长时间回归：`node scripts/validate_long_playback.cjs --url <地址> --browser <浏览器路径> --output <证据目录>`。除了几秒的运动检查，还必须看 277.85 秒和 99999 秒、不同质量和倾角的真实截图。25 项长时间、16 项风格、23 项组合兼容与 12 项交互/数值回归通过，目录分别为 `research/black-hole/workbench-v22-long-playback`、`workbench-v22-styles`、`workbench-v22-compatibility`、`workbench-v22-numerical`。复跑命令和视觉限制见 reference-styles.md。

v2 组合工作台：`node scripts/validate_workbench.cjs --url <地址> --browser <浏览器路径> --output <证据目录>`。23 项检查涵盖非空画面、独立粒子/盘运动、三层光晕、冻结、剑刃粒子遮罩、v2 下载导入往返、v1 缺省、非法字段、视角恢复、时间上限、小图及移动端溢出。v2.1 的组合兼容结果位于 `research/black-hole/workbench-v21-compatibility`；新风格另运行 `validate_styles.cjs`，见 reference-styles.md。经典算法的旧检查显式选择 classic 配方。

可选依赖 Node.js + Playwright 与本机可用 Chromium 浏览器；核心预览只需要浏览器和 Python，不要求安装 Playwright。先启动服务器，再执行：

```powershell
node scripts/validate_preview.cjs --url http://127.0.0.1:8771/ --browser "C:/path/to/chrome.exe" --output "C:/path/to/evidence"
```

浏览器路径可通过 BROWSER_EXECUTABLE 指定；不传则使用 Playwright 配置的浏览器。非标准包目录可按环境设置 NODE_PATH。不要将示例路径当作存在的文件。

检查内容：三配方编译/出图、固定状态重复、旋转动画、零速度冻结、暗核命中、默认路径预算耗尽比例、关闭偏折/移动相机对照、质量档整帧平均亮度、mask 外静止、真实小图、参数验证、配方往返和页面错误。验证保存 validation.json 和截图。诊断 exhausted 是计算截断，不是事件视界。

修复回归另运行：

```powershell
python scripts/validate_server.py
node scripts/validate_regressions.cjs --url http://127.0.0.1:8771/ --browser "C:/path/to/chrome.exe" --output "C:/path/to/regressions"
```

服务器检查使用真实进程和独立临时端口，验证重复启动、SO_REUSEADDR 竞争绑定被拒绝及原服务仍可响应。浏览器回归实际点击控件、导入文件并下载重导，检查视角基准、时间边界、未知字段和错误提示持久性；另外对最薄宽盘、强偏折小暗核、侧视薄盘的 96/256 步输出与测试专用 1024 步同模型参考逐像素比较。`--ui-only` 可只复跑交互部分；`--before path/to/original-kernel.glsl` 可附加旧积分方法的图片，此测试在内存中将其背景 hash 与当前版本匹配，隔离积分改动而不修改原文件。高步数参考是数值对照，不是物理真值。均值检查之外必须看局部条纹。

平均亮度检查仅防止采样数改变导致大幅整体变亮/变暗；不证明轮廓收敛、科学正确或视觉美感。测试中的默认路径预算小于 1% 耗尽仅针对那一组参数，其余配置还需检查。

核心选色回归：`node scripts/validate_core_color.cjs --url <预览地址> --browser <浏览器路径> --output <证据目录>`。检查选色控件、核心命中区域、前景盘遮挡、原生小图、剑刃遮罩、颜色验证与新旧配方往返；可选 `--before <旧内核路径>` 比较黑色默认值与升级前像素。保存 core-color.json 和颜色示例。该检查只验证预览。

## 必须看图的内容

- 暗核可识别，近侧盘在核心前，背面与偏折结构符合设计；图案不是均匀亮圆覆盖整个窗口。
- 极角处无明显接缝；动画改变纹理相位而不重排背景；固定时间转视角与固定视角推进时间是不同变化。
- 面朝、斜视、近乎侧视，以及最薄盘都检查采样条带和漏采。质量档有可见跳变时修改积分，不能只放宽测试阈值。
- 16/32 px 保留主体轮廓与盘面关系，真实物品需要用其具体 mask 再测。仅剑刃示意通过不能证明任意模型。
- 新 shader 的桌面 OpenGL/Forge、其他 GPU、浏览器、光影环境必须分别取证。
