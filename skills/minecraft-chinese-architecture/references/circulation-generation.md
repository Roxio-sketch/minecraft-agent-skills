# 连廊与楼阁的可通行生成

两个入口都生成原创几何；没有从某座古建测绘中恢复榫卯或受力体系。结构回读、净空与路径通过后仍需目标游戏验收。路径节点是脚下方块的XYZ，楼梯/半砖按保守整格占用；算法允许1格跨级，不能替代玩家碰撞模拟。

## 平地直廊与折廊

```text
python scripts/generate_corridor.py --config assets/elbow-corridor.json --out-dir generated/corridor --name corridor
```

`chinese-corridor/1` 的 `path_xz` 是2～16个整数XZ顶点，每段水平或竖直，端点相邻不能重复；允许负坐标。内部净宽 `clear_width` 为3、5或7，两侧柱列与栏杆在净宽之外。端口保持开放，报告给出端口地板中心、向外方向与净宽，供后续组合对位。

| 参数 | 含义与范围 |
|---|---|
| `column_height` | 连续柱材格数，4～12；不含顶梁和屋面连接段 |
| `column_spacing` | 目标最大柱站间隔，4～10；按每段长度均分并取整 |
| `eave_overhang` | 柱侧向外延伸，1～4 |
| `roof_rise` / `roof_curve` | 共享屋面升高1～6，曲率1～2.5 |
| `railings` | 两侧栏杆开关；不是门或活动栅栏门 |

令 `rh=(clear_width+1)/2+eave_overhang`，每段长度需在 `2*rh+2`～160之间，非相邻中心线也至少相隔 `2*rh+2` 格，避免回转廊段意外并成一大片屋面。自交、重走和过近的非相邻廊段会拒绝；没有自动路口、闭合回廊或坡廊。总平面最多10万格，模型总量沿用800万体素限制。

屋面根据整条廊的覆盖范围计算到外缘的棋盘距离，转角共用连续屋皮；不是简单叠放两个带端墙的屋顶。它表达转弯连通，未复原传统转角处的斜沟、角梁和排水。对应真实小尺度材料例见 [siheyuan-study.md](siheyuan-study.md)；该样本的3格材料带不等于本生成器3格净宽，二者不能互换。

生成报告验证整个内部带的两格净空、首尾路径、屋面覆盖、连续柱材和六邻域连通。端口外部仍需接到建筑平台或铺地，不能只对齐图像中的檐口。组合时使用 `voxel_model.Model.paste` 的冲突检查。

## 2～5层楼阁

```text
python scripts/generate_tower.py --config assets/three-storey-hall.json --out-dir generated/tower --name tower
python scripts/generate_tower.py --config assets/mixed-height-tower.json --out-dir generated/tower-mixed --name tower-mixed
```

`chinese-tower/1` 的 `levels` 按从下到上列出 `{bays_x,bays_z,height}`。每层的两轴跨度总和必须为偶数，每个开间4～16格，每轴1～9个；X方向目前要求奇数开间。上层两轴跨度均不得超过下层。

`height` 是**楼板到下一层楼板的高差**，8～12，允许各层不同。顶层使用同一字段确定上部框架和顶屋面高度。柱材连续高度为 `height-4`，报告逐列列出起止Y，不能把楼层高度当柱材格数。

顶部支持既有六种屋顶形态；下层使用中央留空的环状檐面。楼板和梁同步留出同一个西侧U形楼梯井，2或3格宽双跑楼梯通过半层平台折返。各层平台使用统一后缘，较短梯跑前补接地平台，避免混合层高下支撑侵入上一层平台。周边柱架保留内部交通空间，未强行填入完整内柱网。

上层半跨至少X=10、Z=7，还必须通过实际梯井余量检查；这只是前置下限，不能保证最小尺寸容纳3格宽楼梯。梯井、入口走道和上层外墙需要分别留足空间，遇到“不适合梯井”错误应扩大上层体量或缩窄楼梯。

`platform_height` 1～5、`platform_margin` 2～6、`eave_overhang` 2～5、`eave_rise` 1～4、`eave_curve` 1～2.5。所有文件使用原版示例材质；自定义 `palette` 的楼梯、半砖、栅栏角色填基础ID，其余角色可带状态。材料有实际碰撞性质，不能把水或装饰物当承重地板来解释离线结果。

自动检查包括院外到每层室内及半层平台的路径、梯跑每格两格净空、柱材长度、指定护栏位置、几何连通和Sponge回读。测试另检查各跑入口/出口与平台可达、平台三边及顶层井口护栏；封住第一层梯井后，上层必须不可达。这不是完整防坠或结构受力认证，未包含阳台、家具、无障碍竖向交通或游戏操作验收。

普通 `.schem` 是完整建筑。`*_cutaway.npz/.png` 是单独的观察剖切，移除前侧和西侧遮挡，仅用于查看楼梯，不用于施工。其相机旋转只改变预览，不改变结构文件。

## 长阶、深踏面与平台

`chinese-staircase/1` 通过统一 `architecture.py generate` 入口使用，起点为 `assets/ceremonial-staircase.json`。内存组合可导入 `stair_kernel.make_staircase`。这是大台阶的可复用几何内核；已有楼阁的窄双跑梯仍可采用原入口。

- `start_floor_xyz` 指下平台**脚下整块**坐标，`facing` 指上坡方向。第一道楼梯位于前进一格、升高一格处；楼梯低半面朝来路，高半面朝上平台。
- 与平地同 Y 的入口第一排必须是整块下平台；若先铺一排底部楼梯，玩家会先下陷半格再上台。厅堂、楼阁、院门、通门和架空屋的现有入口生成已据此修正。
- `rises` 按同轴梯跑指定升高格数，例如 `[8,8,8]`。`tread_depth` 是相邻升高边缘之间的水平格距。每次升高只放一列楼梯，其后 `tread_depth-1` 列必须用整块地板；不能在同一 Y 连铺相同朝向的楼梯，否则会出现反复下降的锯齿与凹槽。
- `landing_depth` 为梯跑之间的平台长度，`bottom_landing/top_landing` 为首尾平台长度。末端平台与最后踏面顶面齐平，不能继续多升一级。返回 `target_floors_xyz.upper` 用于和楼板、门槛实际对接。
- `target_floors_xyz.upper` 是上平台的**第一排整块**，不是平台中心。跨接折返梯时，用 `top_landing_box(report, depth=2, cross_span=[左界,右界])` 沿来梯的前进方向延伸平段，再横向接到下一跑；不要以出口坐标对称画 `z±1` 或 `x±1`，否则会把末级楼梯覆盖成整块，造成整格跃升。`depth` 不能超过已有上平台长度。转折平台、圈梁和楼板全部拼完后复验每一跑；反例测试会故意覆盖末级踏步并要求失败。
- `width` 为可走的净宽，扶栏、御道浮雕和灯柱放到净宽之外。中央御道如需装饰，应与两侧可走梯跑分开，不能用凸起金块堵住踏面。
- `foundation_y` 指连续支撑下界，默认下平台地板 Y。`headroom` 至少两格，默认三格。组合到高台时显式清理梯跑上方旧台基，并在最终组合上再次调用 `verify_staircase`；非空气粘贴不会自动挖出净空。
- 梯脚与圈梁共用承托时，`solid_blocks` 可补充已核实的整方块基础 ID；保留源码或碰撞形状依据。原版支持形状可直接核验，未知模组方块不会因渲染回退为立方体而自动算作支撑，楼梯、半砖、栅栏和流体不能列成整块。接口还要声明[受保护踏步与平台](tier-junctions.md#楼板与楼梯相交时保留真实踏步)，只留空气不足以保护楼梯形状。
- 模组台阶必须通过 `shape_aliases` 明确映射到已核实相同形状的原版台阶。例如确认类继承 `StairBlock` 后，可将其基础 ID 映射为 `minecraft:quartz_stairs`。不能只凭 `_stairs` 后缀推定碰撞形状。

生成后核对全宽逐列的半格表面连续性、最大半格跃升、踏面与平台平整、底部连续支撑、顶部净空及首尾标高。检查使用声明过的原版形状，不能声称代替了游戏碰撞/玩家实走。至少查看侧面剖切与斜视；整方块预览会隐藏这种台阶错误。

运行 `python -m unittest test_staircase -v`：覆盖四个朝向、1/2/3/5格踏深、混合梯跑、宽梯及结构回读；故意把平踏面换成台阶、反转朝向、堵住净空或挖空支撑，检查必须失败。

## 连廊与楼阁回归

楼阁生成现在逐格检查每层楼板，只有明确的楼梯核心区可被排除；一条可达路径不能掩盖其余楼板缺块。自由叠放的楼层、檐下短墙和裙顶还需使用[楼层接合内核](tier-junctions.md)，检查封檐、柱础承托、四角及最终组合中的净空。

运行 `test_circulation.py`。覆盖直廊、L廊、U廊、负坐标、反向几何一致、封路后不可达、参数/自交/近邻拒绝；楼阁覆盖2～5层、8～12格奇偶层高、混合层高、两种梯宽、逐层收分和文件回读。具体模板是原创选择，`evidence` 中的外部来源只能支持实际采用的规则。
