# 单进院落组合与通路

`generate_courtyard.py` 提供一个可调的院落组装原型：北侧正房、东西两厢、南侧开放入口，外圈院墙与十字铺地。各房间使用 `chinese-building/1` 组件，门向院心。此例没有真实四合院测绘依据；不把中央开放亭门称为传统垂花门，也没有声称实现完整倒座房、抄手游廊或多进院制。

```text
python scripts/generate_courtyard.py --config assets/courtyard-basic.json --out-dir generated/courtyard --name courtyard
python scripts/generate_courtyard.py --config assets/courtyard-cherry.json --out-dir generated/cherry-court --name cherry-court
python scripts/test_courtyard.py
```

输出 `.schem`、NPZ、设计/检查报告和等轴测、俯视、入口方向视图。俯视保留北在上；等轴测和正面展示来自入口的南侧，预览JSON记录 `camera_quarter_turns=2`，没有改变导出结构坐标。

## 尺寸与配置

`schema=chinese-courtyard/1`。`court_width/court_depth` 是四组内向入口台阶之间的设计净院尺度，取24～80的偶数，不是整个结构尺寸。默认28×30院心生成65×27×69的完整结构，包含外墙、后侧空地和入口外铺地。

`main/wing/gate` 分别覆盖厅堂组件参数；`wing` 同时控制左右厢房，旋转方向不同。可用的屋顶与柱网见 [component-generation.md](component-generation.md)。改变房屋尺度后程序会重新计算位置，但过大组件仍可能相交；发生时应改院落尺寸或具体房屋参数，不跳过碰撞检测。

- 正房位于-Z一侧，整体旋转180度，入口朝南。
- 东厢位于+X一侧，旋转270度，入口朝西；西厢相反。
- 南侧入口为开放方形构架，台基限定1格，两侧都有台阶。作为门房原型使用，尚无可关闭门扇。
- `wall_height` 为2～5；`ground/path/boundary_wall/boundary_base/boundary_cap` 分别设置铺地、路径和墙体角色。
- 标准房屋采用奇数面宽开间，门居中；也可选偶数开间与明确 `door_bay`。铺地仍为十字，偏门的寻路可经过周边可走地面；程序不保证偏门自动生成新的铺地转弯。

北侧与左右外墙在房屋边界之外，南墙接入口两侧。默认图中房屋与外墙之间留有空地；不是由历史防火、排水或礼制尺度推算的间距。不同布局任务需要另测依据。

## 通路检查的实际含义

报告保留院外起点、各房间终点及逐步支持地板XYZ坐标。寻路只允许相邻水平格移动，地板高度差最多1格，脚下有方块且上方连续两格为空；跨级时额外检查头部扫过的空间。默认到正房49步、东西厢各48步、入口内7步。

路径使用设计局部坐标。NPZ保留有负值的模型最小点，Schematic则将整个数组最低角作为[0,0,0]；**先减报告里的 `npz_origin_xyz`，再加实际粘贴位置**，才是目标世界格位。不能直接拿路径里的负坐标在游戏里传送。

这是保守的体素检查：楼梯、半砖在寻路里按占用整格，允许的1格变化可能需要玩家跳跃。不是完整玩家碰撞或自动跳跃模拟；透明窗、门状态、模组碰撞、自动连接和游戏光照也没有实机核对。报告不应写成“无需跳跃全程通行”或“游戏内已验收”。

三组测试覆盖入口方向与全路径逐格净空、封路与跨级/低门楣阻塞、院心尺寸变体、偏门、导出往返、确定性及超大厢房相交拒绝。组件之间不同状态相交和院墙冲突会报错；不会用覆盖策略悄悄切开屋顶。

## 后续真实院落学习

继续取样应优先完整住宅总平面，记录正房/厢房/倒座、门与影壁、游廊、耳房、院心及排水关系。庭院中增加树、池、假山后，必须重新验证入口和视线序列；不能把随机绿化当成已实现传统园林。多进院落、连廊、山地接地及多层楼阁仍是独立扩展项。
