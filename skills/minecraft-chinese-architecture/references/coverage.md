# 能力、证据与适用范围

这是100个建筑问题的核对地图，记录**来源实测、可执行工具、实际验证环境**。它不是100个已完成的历史类型，也不把数量换算为掌握程度。逐项状态、文件和限制在 [coverage.json](coverage.json)。

当前本地版本已经形成可用流程：学习资料 → 量柱网/屋面/内部 → 选择功能和场地 → 参数化生成/自由组合 → 输出结构与预览 → 检查格式、几何、通路和目标状态。入口提供19个schema和79份可编辑预设，详细能力见 [SKILL.md](../SKILL.md)。

| 建筑问题 | 当前可执行的内容 | 应继续区分的证据 |
|---|---|---|
| 厅堂、亭、屋顶、构架 | 异距柱网、六种基本顶、多角/圆亭、盝顶/十字/T/扇面、单层重檐和放大构件 | 数学曲面、方块相连与历史构造/受力并非同一验收 |
| 多进院、功能建筑 | 1～4进院、偏门、七种功能组团、14种室内用途及站立目标 | 门扇、家具数不等于房间数；礼制、信仰与机构历史另据资料 |
| 多层、桥廊、塔堡 | 楼层梯井、直折廊、升降廊、廊桥、层塔/密檐、城门/营堡、地下墓室 | 檐带与使用层分别计数；游戏交互和真实碰撞未实测 |
| 园林、宗门、聚落 | 池石、亭廊、月门与视线、地形削填和坡路、沿河双岸、三面院及平顶露台 | 原创组团不等于任何园址或地域的完整复原 |
| 地域住宅 | 架空、窑洞、天井、帐居、圆/方土楼；骑楼、镬耳、二/四攑头、多落院序与单/双护龙空间 | 岭南/闽南已有部分专属原型；其余9项地方类型仍缺专属实现，详见[设计路径](regional-design-atlas.md) |
| 材料与细节 | 材料角色、表面旧化、放大构件；新增有背板的凹凸雕饰与有贯通孔的木质窗屏 | 雕饰已有深度几何；原创新纹样、粗格尺度仍不等于历史彩画和木石砖雕/灰塑工艺 |
| 导入和复原方法 | 调色板Anvil、Sponge、Litematica、Java NBT、明确映射旧投影、指定多区域、尺度控制点、来源传递 | 旧数字ID Anvil不支持；标定工具不自动形成经过历史测绘全面核对的真实遗址复原 |

## 资料的真实状态

- [10份Minecraft来源登记](sources.json)包括世界、独立建筑和合集；格式转换、版本变体、分段大建筑及重复几何不增加独立风格数。
- More Chinese Structures的143个文件完成导入与独立逐格核对，13个文件已有明确局部标注测量；文件数不等于建筑数。[本次九份功能观察](expanded-functional-study.md)补足书架、工作、储物、梯子和门半的关系。
- [16条历史与地方建筑资料](historical-evidence.md)（15份网页正文和1份报告的6个选读页）实际读到具体正文；它们支持遗产地与功能语境，不能替代测绘尺度、具体历史构件或Minecraft实现验收。

当前所有程序验证都是离线。游戏导入、邻接更新、流体、作物、照明和真实玩家通行保持未执行；具体施工任务再进入对应实例。历史真实性与游戏兼容性也分别判断，不能以测试数量替代其中任何一项。

## 新任务如何扩展

先选能带来新空间关系的资料，如未取样的地方户型、可核对木作节点、具体雕饰或真实测绘。不要为增加下载数量重复获取相似大殿。`Asian`、`Oriental`、`Pagoda`等标签只保留原声明；文化、地域和年代归属需其他证据。

把得到的新值写入带哈希的标注，做出可用参数或独立组件，再检查它解决了什么实际建筑问题。已有工具适用时直接生成；不适用时明确做新设计，不能把未实现项目改一个状态标签就算完成。
