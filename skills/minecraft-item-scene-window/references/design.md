# 自由设计与空间契约

收到“剑里是漂浮城堡/森林/星球系统/另一个房间”等描述，先组织主形、观察方式和承载物，不让用户填技术参数。

| 维度 | 自由决定 |
|---|---|
| 内部内容 | 手工几何、复杂 mesh、方块/实体展示、程序场混合或真实世界视角 |
| 场景 | 主体、前景遮挡、中景、远景、留白、尺度、层级 |
| 动态 | 旋转、轨道、位移、骨骼、粒子、交互、暂停 |
| 相机 | 固定展示、观察者对应视差、轨道、反射或异地相机 |
| 开口 | 矩形/圆/菱形、任意 mask、模型材质区域、多孔、多窗口 |
| 组合 | 原材质、内部 Cosmic、玻璃壳、Halo、glint、bloom |
| 质量 | 16/32px 主形、手持细节、刷新率、分辨率、同屏预算 |

“房间”需要墙/家具/空间关系，不能只给默认观测站换色。“看见另一维度中的生物在行走”需要世界/实体更新链路，不是放几颗彩色立方体。

## 当前实现与扩展空间

模板支持 box、任意三角列表 mesh、group，节点可嵌套，位置/旋转/缩放/颜色/旋转速度可改。相机 offaxis/fixed/orbit；窗口 rectangle/circle/diamond/外部红通道 mask。box 固定分面明暗，mesh 单色。是真实三角形和深度测试。

目前没有 OBJ/glTF 导入器、纹理网格、动态光/阴影、世界方块实体、骨骼/轨道脚本。复杂 mesh 可预先三角化写入，多个颜色拆节点。其他材质/运动扩展 parser 与 Backend，更新格式说明；方法不限于模板，但交付应区分实现和设计目标。

## off-axis

局部窗口 z=0，x/y 四边±0.5，内容在z<0；眼位 E=(ex,ey,ez)，ez>0：

```text
left   = (-0.5-ex)*near/ez
right  = ( 0.5-ex)*near/ez
bottom = (-0.5-ey)*near/ez
top    = ( 0.5-ey)*near/ez
view   = translate(-ex,-ey,-ez)
projection = frustum(left,right,bottom,top,near,far)
```

场景点P投到窗口平面的x为 `(ez*x-ex*z)/(ez-z)`。z=0时恒为x；后景随眼位变化。用此数学关系检查，而不是只验证像素变了。不同宽高的窗口同时改四边和映射，不能只拉伸最终纹理。

固定模式不跟随观察者，轨道模式是自动展示镜头。各有用途，不将它们称为观察者视差。当前背面把眼位翻到另一正面，适合双面展示牌；真正双向空间盒需要另行处理厚度和投影。

内部深度用于节点遮挡。虚拟物体不会自动突出到玩家所在世界；跨界物体需另一项几何/裁剪任务。多面连续窗口不能给每面独立贴正面视图后声称连续。
