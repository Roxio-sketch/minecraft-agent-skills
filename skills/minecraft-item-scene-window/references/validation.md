# 验收方法

先配置验证，再构建/reobf，再在授权Forge1.20.1环境检查画面。源码/数学/GPU统计/游戏截图是不同证据。

1. 固定time，eye.x=-0.6/+0.6。窗口平面控制点不滑动，前后景相对位移不同；不能用动画代替视差。
2. 前景杆遮住后景，移眼后露出；深度缓冲有多个非背景值，并结合截图检查顺序。
3. 固定眼位，time=0/4秒。静态杆稳定，动画节点变化。
4. 矩形、圆、菱形、用户mask；洞外不写深度，后续原版物品/文字不受污染。
5. 多场景同屏A-B-C-A不串图；新增缓存后测同scene不同眼位。
6. GUI大图和16/32px、第一人称左右手、第三人称、掉落/展示框逐项记录，不凭共享入口推断通过。
7. 重载、分辨率切换、窗口resize、退出/重进，检查shader代次、FBO完整性和绑定恢复。
8. 世界backend增加快速转头、区块未就绪、断开、嵌套与渲染加速mod测试；骨骼、glint、bloom分别验收。

命令 `/scenewindow preview` 展示；`/scenewindow verify` 限ASTRA_VFX_TEST单人测试存档。后者暂时改背包选中项/显示设置并记录恢复。复跑前备份；获得物品可能解锁配方/进度，不是世界字节级回滚。

本地文件桥 `<gameDir>/item-scene-window-lab/request.json` 的 `{"action":"run"}` 可触发测试，消费后删除；preview只打开画面。输出runs/<time>包括主画面、内部FBO图、深度统计、代次和恢复结果。不默认启动游戏。

模板自报值不足以证明画面正确，核对截图、产物和部署哈希。失败/超时跑次保留。性能基准另测，不从几何数量或单张图估算FPS。

模板内 `scripts/validate_runtime.py <run目录> [--built JAR --deployed JAR]` 使用 Pillow/NumPy 独立验证。它检查深度与 GL 数值、每个手持上下文的新增绘制次数、洋红远景的视差方向/量级、静止地板与动画差异、重载像素一致性、原版控件区域和恢复记录。FBO 截图是该帧最后一次绘制的目标，可能来自 GUI；不要把它当作手持视点，手持使用主画面和 `contextEyes`。

截图审阅仍需确认实际可见和合适的展示姿态。自动检查只覆盖声明的 FBO/深度写入状态，并不证明所有第三方 OpenGL 状态均兼容。
