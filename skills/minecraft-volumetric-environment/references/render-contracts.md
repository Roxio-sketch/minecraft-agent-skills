# 世界体积环境渲染合同

本合同服务 `world-volume/2` 的原创有限世界介质。参考包提供机制证据；工作台和 Forge 的完成状态以该模块 `VALIDATION.md` 及实际报告为准。这里列出要实现、审查与验证的条件，不把要求自动标成已通过。

## 介质、光源与表面分开

| 合同 | 计算输入和出口 | 必须能独立验证 |
|---|---|---|
| 自发光介质 | 世界位置的发光调制与介质密度，沿视线路径累积辐射；不自动向地形加光 | `emission>0`、云受光与表面光关闭时，只有可见介质增亮；主透射不因 glow 强度改变 |
| 局部光照云 | 同一个事件世界位置/颜色/包络；有限距离衰减；通过介质密度估计光路透射；在视线积分处加入散射 | `emission=0`、`surfaceGain=0`，切换 `mediumGain` 只改变云雾；无密度时局部散射为零 |
| 局部光照表面 | 同一个事件，在真实表面世界位置和法线上算光；在视线介质合成前加入场景 | `emission=0`、`mediumGain=0`，切换 `surfaceGain` 只改表面源色；空间衰减和法线朝向必须存在 |

`mediumGain` 与 `surfaceGain` 不能偷偷联动。所有通道读取同一次 `veFlashState()` 的语义，不各自生成不同事件。不把全屏泛白、Bloom 或闪电枝条几何当作这三个合同的替代。枝条几何可由独立 lightning skill 协作；屏幕 Bloom、动态 block light 与局部光的地形阴影需要额外能力。

本版局部光射线只使用介质自遮挡，无地形 shadow map/光源深度立方体，因此遮住相机视线的建筑可以截断体积，但建筑在光源与其他点之间不保证挡光。表面合同是直接辐射近似，不写入 Minecraft 方块亮度，也不认证全局照明。

## 世界位置和有限支撑

位置以方块为单位，`p=origin+normalizedDirection*t`。介质使用固定世界中心；相机移动只改变射线与采样位置，风在秒级时间上平移/扭曲密度。若需要跟玩家移动的艺术区域，应明确提供跟随模式，不能把无意的相机锚定误叫世界密度。

`Bounds.xyz` 为中心、`Bounds.w` 为外半径。`shape=0` 是受水平半径截断的高度层/圆柱，`shape=1` 是球，`shape=2` 是带中央空洞的环状高度层。高度层的底/厚度来自 `Layer.xy`；球的高度来自中心和半径。形状之外密度必须为零；允许用保守外包体计算积分区间，但每一个实际样本仍须检查精确密度支撑。

平行高度面、相机在云内/云上/云下、球切线、无命中、近零长度均需有限结果。所有 sqrt、除法、pow 的定义域须安全。大坐标应在 double 中减世界中心/重定位原点后再传 float，不能把 ±3000 万的 float 密度无条件称为稳定；若实现只传绝对 float，应把远坐标精度列为限制。

“云海”属于形态与视点合同：高覆盖、连续层、可从上方看到局部云顶、穿越云层时有遮蔽和位置视差。距离雾、单层平面云、多个二维高度平面、首次命中云搜索与连续三维密度积分应分别命名，不按函数中的 volumetric 字样归类。

## 深度重建与积分

宿主向核心传真实场景距离，不能把非线性 depth 值直接当作格数。使用实际 inverse projection、inverse view 和当前 framebuffer 的 UV/depth 重建世界终点；天空深度走有限区域边界。Minecraft 1.20.1 的 bob 可能写进 projection 平移，光学眼点与世界射线应与表面终点采用相同投影合同。只移除 view translation 并不能证明无摇晃错误。

取实际射线区间与 `[0,max(sceneDistance-bias,0)]` 的交集。低分辨率体积结果必须按深度拒绝跨边缘的样本；没有合格样本时贡献为零，不能通过归一化极小权重把天空介质漏到细前景。优化需单独验证前景边缘与时间重投影，完整当前帧版本先提供可审查基线。

密度 `rho>=0`、消光 `sigma>=0`、步长 `ds>=0`。核心透射为 `Tstep=exp(-rho*sigma*ds)`，源辐射按当前透射累积，再更新透射。输出 `veIntegrate` 的 rgb 为预乘累积辐射、a 为透射；最终是 `scene*T+L`，a 不是覆盖率。零密度/零长度必须精确返回 `(0,0,0,1)`。

步长乘数是必需的；不能只把噪声值逐样本相加再 clamp 并称作同一消光模型。若发光是每单位路径的独立辐射项，应按步长和透射积分；若采用密度比例发光源，应明确它随 `rho` 消失并区别于完全独立发光场。本版优先使用密度比例发光，方便三通道开关对照。

仅用当前帧中点积分时，固定输入重复 draw 应一致；增加/减少步数可以改变误差和性能，但不能改事件编号/种子/密度语义。最多 96 视线样本、12 光线样本是预算边界，不是性能保证。球形相交与带厚度高度层不同，应分别处理。

## 事件时间

`Time` 单位是秒，负值夹为零。事件编号为 `floor(Time/flashPeriod)`；种子和事件编号决定位置及脉冲时机，事件包络由当前秒级局部时间计算。一个周期一个事件的模型应明确描述，不能声称已实现任意泊松风暴或 Bliss 的随机倒计时分布。

暂停时间冻结密度运动、发光变化和闪光；同一个时间/种子/配方重载后应重放相同结果。30/60/144 FPS在相同采样时间上的状态应相同。暂停后恢复可以继续既有时间或明确重新开始，不能隐式把帧号当秒。超长运行时间可能损失 float 秒精度，宿主应提供时间重基准或限制说明。

## 色彩与表面采样

工作台可使用 linearSceneRGB，源辐射与场景在一致线性空间合成并只在最终显示时编码/映射。Forge 主颜色附件若是已经曝光的显示颜色，必须明确解码或使用已曝光场景上的艺术近似；不能仅因函数名 `linearScene` 就宣称端到端物理色彩管理。

有真实场景法线/albedo时优先使用它们。仅由屏幕深度有限差分重建的几何法线无法认证所有材质、透明表面、边缘或法线贴图；应拒绝天空/无有效深度并保护前景不连续。表面直接加光发生在雾合成之前，使其再受相机到表面的介质透射影响。

## 透明和渲染所有权

一张最近不透明深度可以保证积分终点在该面之前，但无法分离多个透明表面前后介质。后处理已有玻璃颜色不等于玻璃后方雾正确；透明表面受到局部光也不等于透明介质完成拆分。默认声明单个不透明终点路径；原版水/玻璃、Fabulous及自定义 RenderType要有专门 hook 与独立证据才扩大支持。

外部 shaderpack 激活时必须有明确的环境所有权。默认交给 shaderpack 并跳过原创体积绘制/构建，避免两套深度和场景颜色合同叠加；关闭后可恢复自身路径。这里只是集成策略，不是任意包或 Iris/Oculus版本兼容认证。

新模块保持独立资源 namespace 与配方 schema。现有天空工作台及其环境共享依赖继续保留。不要凭旧 `cosmic-sky-lab` 报告认证新模块；每次发布绑定真正编译/加载的 Java 类、GLSL资源、核心哈希与采集范围。

## 最低验收矩阵

| 对照 | 要检测的失败 |
|---|---|
| 云下/云中/云上，移动与转向 | 角方向图片假装世界密度；相机跟随；形状支持错误 |
| 建筑前/后、细柱、天空边缘 | 未重建深度；步长越过终点；低分辨率泄漏 |
| 自发光/云受光/表面受光单独切换 | 通道联动；全屏亮度替代局部光；密度和发光混淆 |
| 同一时间重复 draw、冻结、资源重载 | 帧率依赖、隐式历史、事件变位 |
| 无密度、最大密度、球切线、平行射线 | NaN、Inf、错误透射或非法定义域 |
| 自身渲染与外部光影开关 | 重复合成、错误所有权、关闭后未恢复 |
| 透明场景（如已适配） | 只完成表面光却宣传完整后方雾 |

浏览器 GPU 编译/浮点结果、配方协议、Forge编译、真实游戏采集分别记录。构建成功不认证实际游戏画面；截图也不代替同时间开关/深度/源哈希证据。失败记录保留，修复后新增报告而非覆盖旧失败。
