# 路线选择与对象分层

## 三种后端，按任务选择

| 后端 | 获取信息 | 优势 | 不足与升级条件 |
|---|---|---|---|
| A：地形阶段位置重建 | 原颜色、地形深度、同帧矩阵；可估法线 | 复用原地形几何，接入面小；后画实体自然不替换 | 不含方块实体/透明层；不是所有方块类型选择器；原光照/雾已合成 |
| B：分类/辅助缓冲合成 | 深度、category/coverage、normal、albedo/light 等按需生产 | 细分对象，统一多区域，空间材质灵活 | MRT 或分类重绘/注入成本；必须保证附件与可见表面、alpha discard、骨骼姿态一致 |
| C：原绘制中的材质函数 | 原顶点/片元世界位置、纹理、灯光、分类 | 可在原 fog/透明混合前替换，最完整的真实材质语义 | 每类 renderer/顶点格式/第三方 shader 都需适配；不简单替换 RenderSystem shader 就能覆盖所有地形 |

建议先 A 验证空间与风格，再按需求加 B/C。严格保留原光照、需要透明水面本身的世界位置、只选某类方块/实体时，B/C 是必要信息来源。可以组合：地形 A，实体/水 C，边界与 bloom 独立 pass。

0.2.0 的水/透明区块已提供一条受限 C 实现，见 [透明表面](transparent-surfaces.md)。该实现在原透明 draw 内逐片元处理，不从单个最终深度恢复所有层；基础/材质化/完全异化是效果能力等级，与 A/B/C 数据接入路线是两个不同维度。

“屏幕空间执行”与“屏幕滤镜语义”不同：用全屏三角查询原表面 world position 并计算三维材质，仍能保留可见几何；但它只能处理已有可见层，不会恢复遮挡后的几何或改变真实材质的所有光学属性。复杂折射/镜面/阴影不能从单张颜色深度无损推导。

## 通用数据流

```text
RegionStore（逻辑、维度、时钟、对象策略）
    → FrameSnapshot（插值后的不可变区域表、材质参数、资源代次）
SceneCapture/DrawAdapters（颜色/深度/矩阵/可选 normal, category, light）
    → CandidateCulling（视锥/屏幕包围/区域 tiles）
    → SurfaceReconstruction → RegionMask → MaterialEvaluation
    → SurfaceLighting/Fog → BoundaryEmission → OptionalBloom
    → Composite（颜色；保持原深度）
    → 后续实体/透明层/手部/UI（按选定策略）
```

无区域时零额外 draw/副本；先廉价 Mask，再执行昂贵材质函数。每个 pass 契约包括输入/输出附件、空间、分辨率、格式、时机、owner、清理、深度写入和错误回退。MRT 配置不自动让任意 shader 写出正确法线/类别。

## 对象策略矩阵

| 对象 | A 基线行为 | 要实现更完整能力 |
|---|---|---|
| solid 地形/建筑 | 已深度测试的可见表面可替换 | 精确 blockId/tag 需重绘分类或 chunk mesh 属性，不能按颜色猜 |
| cutout 草/树叶 | 利用原 discard 后的深度保留孔洞 | 分类 pass 必须复制 alpha cutoff、sprite 动画与双面规则 |
| 方块实体（箱子等） | 后画，保持原材质 | 在 BE draw 路径接入，或输出独立类别；方块实体不是实体类别的同义词 |
| 普通实体/玩家 | A 后画，不替换；仍按原深度遮挡已改地形 | 选中实体需要覆盖其真实 renderer，包括骨骼、armor layers 和透明子层 |
| 水/半透明玻璃 | 原透明层后续合成，能看到已改后的背景；自身材质未改 | 捕获真实层的位置/normal/alpha，在该层混合前替换；多层需分层或 OIT 方案 |
| 粒子 | 默认排除并在后续绘制 | 仅需要时为指定 particle renderer 提供材质/类别，不用其近似深度污染地形 |
| 天空 | 无有限有效深度，默认跳过 | 另定义视线与区域体积相交的视觉；与环境表面替换分开授权/实现 |
| 雾/云/天气 | 云/天气是单独 pass；base 常已含雾 | 表面材质 fog 一次；区域体积雾另算；不可把 fog 颜色反除还原 albedo |
| 第一人称手与 GUI | 默认排除 | 另接物品 skill；不要世界结束后读被清理/改写的手部深度 |

半透明反例：相机看到水面下的地面，最终深度可能指向水底。仅按这个深度的球形 Mask 给“水”着色，会按错误的高度判断，而且一次处理已混合颜色无法独立选中后方地形。默认排除透明表面的**材质函数**并不保证透明像素最终 RGB 不变，因为其背景可以改变。

类别数据必须以未混合或明确编码方式保存；让整数 ID 跟透明 alpha 混合会产生无意义类别。screen category 只能标识一个层，不能表示整条视线中的所有透明物体。

## 光照、雾与信息损失

普通 sceneColor 通常是 albedo×灯光/AO/tint 再 fog 的结果，不能稳定反求分量。材质有三种明确策略：

- 自发光替换：输出自身颜色，可显式应用当前 fog；接受区域内原 AO 可能丢失。
- 原光照保留：生产光照/AO/normal/albedo，或在原 shader 合适位置替换 albedo 后继续原照明；仅把最终 sceneColor 亮度当遮蔽属于美术近似。
- 自定义照明：使用获取的数据重新着色；不意味着改变 Minecraft 方块光等级或真实投影阴影。

源颜色与新材质统一工作颜色空间。HDR 累计、曝光、gamma/tone mapping 所属 pass 明确，避免双转换。对象与天空边缘采样严格使用有效 coverage，模糊/扭曲不能任意泄漏区域外。

## Stencil 的正确角色

可用 stencil 标识屏幕候选区域或特定几何类别，以减少昂贵片元；它不直接给世界距离。一个球壳在屏幕投影内，远处不在球内的墙也会落在相同投影内，因此 stencil silhouette 不足以替代深度位置 Mask。

需要体积 stencil 时处理相机在内部、前后面、near-plane 和 depth-fail 等情形，并遵循目标附件对 stencil 的支持。共享 stencil 必须有所有权/位约定，不随意清空其他 mod 的标记。Immersive Portals 的区域清深度/恢复门面深度是门户用法；本任务基线不清原世界深度，也不渲染另一世界。
