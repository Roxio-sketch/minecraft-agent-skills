# 水面为何保留原色：当前后端的明确限制

本页保留 **0.1.0 地形后端**的诊断记录。之后的 **0.2.0** 增加可选原透明几何材质注入，见 [三级透明模式](transparent-surfaces.md) 和 [新增实机验收](surface-validation.md)。下面的“当前后端”只指 0.1.0/基础模式，不能用来否定新透明路径，也不能借新路径改写旧证据。

2026-09-29，针对实机对照图中的水面重新核对。结论针对图中“原蓝色水层上/下可见 Cosmic 或熔岩图案”的现象：**当前地形后端改变了水下不透明表面，水面自身未做材质化；这是当前能力边界，尚未查到导致该现象的管线故障。** 不代表完整水面效果已经实现，也不代表所有透明渲染问题都被排除。

## 已核对的实际顺序

目标是 MC 1.20.1 / Forge 47.4.10 的 Fancy 管线：

1. LevelRenderer 绘制 solid、cutoutMipped、cutout。
2. 本工程在 AFTER_CUTOUT_BLOCKS 读取颜色和深度，对已有表面计算世界球 Mask，只修改颜色。
3. 随后绘制实体/方块实体，再绘制 RenderType.translucent 的水层。
4. 水面沿用自己的纹理、颜色与 alpha，将它们混合到已经改变的水下背景上。

本地映射类 ItemBlockRenderTypes 将 WATER / FLOWING_WATER 映射到 translucent。RenderType.translucentState 选择原版 translucent shader、方块图集、lightmap 和透明混合状态。RenderStateShard 的 TRANSLUCENT_TRANSPARENCY 显式启用 SRC_ALPHA / ONE_MINUS_SRC_ALPHA；原版 rendertype_translucent.json 声明同样的 RGB 混合，ShaderInstance.apply 应用它。这里没有证据表明水继承了材质 pass 的“关闭混合”状态。

单水层可用下式解释（实际还可能有雾、多个透明面）：

`最终颜色 = 水层颜色 × alpha + 已变材质的水下背景 × (1-alpha)`

因此星点/红色裂纹会通过水显示，并带原版蓝色；图案取样位置是水底、岸壁等原表面，未承诺位于水面高度。水面与岸边观感不统一、图案像在水下，都可由此解释。它不是波面反射/真实折射，也不是水面材质完成后的产品效果。

## 三种需求必须分开

| 用户要求 | 需要的处理 |
|---|---|
| 水面仍是原版水，能看到改变后的水底 | 现有后端的行为；说明背景颜色会改变最终水像素 |
| 水面也变为 Cosmic/水墨/熔岩等视觉材质 | 取得流体表面的真实位置、normal、alpha 与类别，在流体原绘制/混合前评价区域材质；单独考虑流动、侧面、水下视角与多层透明 |
| 所有水覆盖的屏幕像素完全保持原画面 | 额外捕获水覆盖信息和未修改的底层结果，明确合成政策；仅仅不修改水 shader 不够 |

不通过把 post pass 移到 AFTER_LEVEL、给水面硬盖不透明星图、关闭透明混合或按蓝色猜水来“修复”。这些做法改变对象选择/遮挡语义，容易误伤实体、玻璃或背后场景。也不要无区别替换全部 translucent shader 来冒充仅处理水。

## 验证范围纠正

此前 14 份 probe 是本材质 pass **前后**的地形附件检查，发生在后续水层绘制之前。它们证明该 pass 保持原地形深度、所定义范围外颜色不变，不能证明水面材质化、每层透明混合或透明对象分类正确。

本次主要依据原实机截图、现有源码与本地 1.20.1 映射类/原版 shader 复核。尝试重新采集 off/hold/off 对照期间，客户端离开存档进入标题界面；该次运行对照未完成，不计作新实测。没有修改生产 Java/GLSL 或游戏 jar，没有新增水面实现认证。

将来扩展水材质时至少检查浅水/深水、静水/流水/瀑布、水下视角、岸边、透明面叠层、实体穿水、范围边界在水面与水底不同位置的情况。所需数据与后端选择见 [architecture.md](architecture.md)。
