# 功能覆盖与连续叙述

## 每次制作的工作记录

覆盖表至少写出功能、展示操作、预期可见变化、配方 / 种子 / tick / 视角等控制条件、素材路径、章节时间和证据状态。镜头长度由信息量及实际旁白决定，示例时长不作为上限。

把覆盖状态区分为 planned、captured、reviewed：有素材文件不代表已经看清或已证明功能。正式交付前关键功能达到 reviewed，无法验证的能力明确说明。

视觉效果项目常见证据：

- 多形态：不同轮廓 / 材质，不能只改标签；同一个主体改变配色可补充颜色自定义证据。
- 参数：控件改变和效果改变同镜头出现，避免 UI 挡住主体。范围展示使用背景参照或同一对象，开关对照保持相机稳定。
- 事件效果：展示正常生命周期；固定 tick 的静态调参镜头只用于读清参数，不代表真实动画节奏。
- 实现边界：区分视觉与游戏逻辑、演示适配与正式发布、工作台预览与游戏内渲染，避免推断未验证的性能或兼容性。

## 连贯文案

先展示效果，再解释一个问题，然后自然进入下一个。例如：“盘面确定以后，再换一组冷色。接下来保持这个配色，只调整厚度，看轮廓怎样变化。”旁白与画面共同传达信息，不把每个标签再念一遍。

相关对照放在一段里，例如透镜开关 → 范围 → 人物参与 → UI 操作，随后再转到另一功能。复用同一素材时确认确有新的说明目的。

## 交付目录

最终目录优先少量明确文件：配音版 MP4、用户需要的无配音版、每条视频 PNG/JPG 封面、标题简介 TXT、配乐署名、字幕 / 原始旁白、检查报告。原始素材与源码留在工程内。检查图临时保存到单独 QA 目录，封面修改仅导出封面。

新项目无需重新配置已经可用的整套工具。工具路径、工程目录、音色服务地址和输出位置作为配置；路径缺失后发现替代，不照搬另一台机器的绝对路径。
