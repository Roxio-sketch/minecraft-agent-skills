# 诊断与验收

先定位最后一个有证据的环节：资源存在、注册成功、新实例回调、uniform 上传、draw 提交、正确输出目标、最终画面。分别检查 shader 编译/链接、JSON 解析和顶点接口，不把这些统称为“GPU 不支持”。

| 症状 | 优先验证 |
|---|---|
| 黑屏/完全没效果 | hook 是否运行；当前实例是否非空；常量色 draw；scale/opacity/mask；编译日志和目标 framebuffer |
| 移动就漂移 | 是否误用了相机位置/屏幕 UV；到底是无限远背景还是应有视差的局部体积 |
| 转头不正确/方向反了 | 实际 Camera vs 玩家旋转；世界/眼空间符号；半角；矩阵转置/重复变换；独立参考自身是否错 |
| FOV或窗口变化后拉伸 | 当前实际投影、viewport/framebuffer 像素尺寸；固定 zoom、旧矩阵、GUI尺寸 |
| 重载后黑屏 | 实例回调更新；旧 uniform/atlas 句柄；资源名；活跃参数；引用可变数组导致 dirty 判断失效 |
| 星空覆盖地形 | 天空 pass 时序、depth write、延后队列、是否清深度或再次全屏合成 |
| 体积在边缘穿透 | 沿射线距离与 -viewPos.z 混用；深度纹理来源/时序；背景深度和裁剪范围 |
| 局部面不可见 | 面 winding/cull、视锥、内外表面、RenderType 的 EQUAL 是否匹配承载几何 |
| 接缝/极区异常 | 整条经纬度运算周期性、独立立方体面 UV、邻域截断、sprite 过滤边界 |
| 开光影后失效 | hook 是否仍执行；Shader Pack 的 framebuffer/viewport/矩阵/深度来源；队列消费时机；布尔 helper 实际逻辑 |

## 验收范围

无限远天空的基础测试：固定时间，平移、旋转、FOV、resize、资源重载、地形遮挡。方向图检查中心和边缘；用独立基向量/几何事实交叉验证。遮挡至少保存天空 pass 和最终帧，不能仅检查“中心颜色变了”就宣称所有物体遮挡正确。

针对改动扩展：第三人称、相机模组、摇晃/受伤、流体、天气、透明物体、全天球接缝、长时间动画、其他 GPU/分辨率。若用户要 Shader Pack 兼容，固定 MC/Oculus/包版本，分别测开关、第一/第三人称、GUI、目标 framebuffer 和重载；原有普通客户端结果不能替代。

读回前确认通道布局、sRGB/后处理与像素原点。GPU timer 的结束放在读回截图之前，等 available 再读取 query；CPU profiler 另测状态查询和分配。不把没有 GL error 当作视觉正确。

## 证据表达

- 静态：能定位资源、方法和直接调用；若无消费者，仅写“本次范围内未找到”，不猜作者意图或断言绝无反射调用。
- 编译：Java 编译/重混淆通过；不意味着驱动已编译 GLSL。
- GPU 运行：实际驱动加载和 draw；画面截图另看。
- 数值：明确比较空间、像素、阈值与输入，记录失败项而非只输出 pass。
- 视觉：说明看过哪些图，区分审美评价与几何正确性。
- 性能：硬件、分辨率、场景、预热、测量区间、样本与统计。未测不能给出保证。

修改验证器时保留失败记录，证明为什么参考错误，避免同步改参考和被测实现掩盖真实缺陷。模板检查器验证记录一致性和文件完整性，不能证明记录不可伪造、PNG 内容与记录完全一致或所有 GPU 状态正确。
