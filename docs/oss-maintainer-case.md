# 项目维护与 Codex 使用计划

## 项目解决的问题

Minecraft 特效开发跨越 GLSL、模型变换、深度、FBO、配方校验、构建和游戏验证。这个项目把实际开发经验整理为可复用 Codex Skills、可调工作台、源码示例和有边界的测试记录，帮助开发者从效果描述推进到可核验的实现。

该集合现公开 23 个渲染 Skill 与 32 个工作台/预览/研究入口。涵盖天空、大气、体积环境、物品材质、护盾、闪电、拖尾、粒子、局部空间和 GPU 优化。普通预览无需 OpenAI API key；新增 API 维护自动化不会成为使用现有工作台的前提。

## 维护证据

- 主要维护者 GitHub：Roxio-sketch；功能、工具、文档和发布持续维护。
- 既有黑洞/闪电发布与 Cosmic 材质发布保留在 Release 历史。
- 本次公布全量功能目录、安装入口、许可来源和按日期保留的五行仙途开发记录。
- 上游贡献：[minecraft-mod-mcp Issue #36](https://github.com/langyo/minecraft-mod-mcp/issues/36)、[PR #37](https://github.com/langyo/minecraft-mod-mcp/pull/37)。它们证明提交过问题和修复，不据此声称上游主要维护者身份或 PR 已合并。
- 炉底近距性能问题形成公开性能 Skill，包含配对 GPU 计时、硬件/分辨率、质量取舍和后续视觉问题，见 validation-and-evidence.md。

## 使用规模

项目处于早期。公开 Star 和下载量以申请当天 GitHub 数据为准；不把本地实验次数、文件数量、其他上游的 Star 或用户个人使用量当作本项目采用度。尚无经核实的大规模社区采用证明。本次公开提高可复用性，但不声称上传即获得生态影响力。

## API 额度的计划用途

1. 问题分类：从用户的版本、渲染管线和复现信息生成可维护的检查清单。
2. PR 审查：辅助审查 shader/Java/配方一致性、GL 状态恢复和渲染阶段变更，由维护者审核后合入。
3. 文档和发布：同步工作台参数、Skill 说明、兼容范围和 Release 文档。
4. 回归评估：建立固定 seed/time/camera 的效果用例，区分静态检查、GPU 结果和游戏实测，保留失败数据。
5. 维护自动化：辅助生成复现工程和测试计划，逐步公开可重复的脚本。

这些是拟实施的维护工作流，不表述为全部已经接入 OpenAI API。测试、代码和维护文档的改进将公开回馈项目。Codex Security 如申请，仅针对有权限的仓库；当前最直接的需求是 API 维护额度和日常 Codex 编码/评审支持。
