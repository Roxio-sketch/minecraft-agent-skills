# Codex 开发任务：流星御空第二阶段——高级视觉精细化

## 一、开发目标

请检查当前 Minecraft 修仙 MOD 工程，继续对已经实现的「流星御空」飞行系统进行第二阶段视觉升级。

本次目标不是重新制作基础飞行特效，而是将已有的玩家飞行姿态、球形灵气护罩和流星尾焰升级为更精致、更立体、更具有仙侠气质的动态视觉效果。

重点实现以下内容：

1. 光球的立体感、流动感和动态形变。
2. 尾焰的三维体积感与多角度可见性。
3. 流星头部与尾焰的连续过渡。
4. 灵气在球体表面的高速流动。
5. 尾焰内部的能量脉动与层次变化。
6. 加速、减速、转向时的视觉反馈。
7. 玩家动作与光球、尾焰之间的动态联动。
8. 更自然的拖尾运动、消散和残影。
9. 高速飞行时的整体视觉统一性。
10. 特效性能优化和参数集中管理。

请先检查上一阶段的实际代码。

如果第一阶段的某些功能尚未实现或者存在明显错误，先修复影响本阶段实施的基础问题，再继续。

不得假设上一阶段已经完全实现。

不得无关地重写整个飞行系统。

---

# 二、整体视觉方向

最终特效应该具有以下特征：

玩家被一颗半透明的青蓝色灵气光球包裹。

光球表面存在沿飞行方向高速流动的灵气。

光球前端具有略微集中的能量亮度。

光球后半部不断向后释放灵气，汇聚成流星尾焰。

尾焰具有真实的三维体积，而不是几条平面发光丝线。

流星高速运动时，尾部能量会被拉长，产生自然的流动、震荡和消散。

转弯时，光球保持完整，尾焰沿历史轨迹形成弯曲的流线。

整体风格为：

**仙侠灵气 + 彗星尾焰 + 高速御空 + 半透明能量护罩。**

必须保持 Minecraft 的风格协调性，避免过度写实的火焰和复杂粒子堆叠。

# 三、光球高级优化

## 3.1 球形能量层次

在现有球体的基础上完善三层视觉结构。

### 第一层：内部灵气

玩家周围存在非常淡的青蓝色能量。

要求：

- 透明度高。
- 不遮挡角色皮肤。
- 不形成完全实心的发光球。
- 允许少量柔和的色彩变化。
- 内部保持视觉干净。

建议基础 Alpha 约 0.04～0.10，实际取值根据混合模式调整。

### 第二层：球形能量外壳

这是光球的主要可见轮廓。

要求：

- 球形完整。
- 边缘比中心明亮。
- 使用视角相关的边缘亮度变化。
- 不同观察角度都能看出球体形状。
- 球壳不得出现明显的多边形断面。

如果当前渲染管线适合自定义 Shader，可使用 Fresnel 边缘增强。

否则使用现有支持的分层网格近似实现。

不要强制引入额外渲染库。

### 第三层：球面流动灵气

在球面生成少量弧形流光。

特点：

- 数量少，建议 2～4 条。
- 粗细存在细微变化。
- 沿球面弯曲。
- 随时间缓慢变换位置。
- 随飞行速度调整流动速度。
- 视觉上具有向后流动的趋势。

注意：

不能生成过于完整、规则的光环。

不要让球体变成机械陀螺或被多个圆圈包围的装置。

灵气应当贴合球面流动，而不是远离球体漂浮。

# 四、光球动态形变

这是本阶段新增的重点。

## 4.1 低速状态

光球整体接近标准球形。

前后比例基本一致。

表面流光较慢。

## 4.2 高速状态

当玩家高速前进时：

- 光球可以沿飞行方向轻微拉伸。
- 横向宽度可轻微收缩。
- 前缘更集中。
- 后半球向尾焰方向形成自然的能量过渡。
- 流光运动速度提高。

建议最大纵向拉伸比例为 1.05～1.15。

禁止把光球拉成一根长椭圆。

必须让玩家始终处于能量球内部。

## 4.3 转向状态

玩家快速转弯时：

- 球体主体仍保持圆润。
- 后缘能量可以稍微滞后。
- 球面流光向转向外侧产生轻微偏移。
- 尾焰继续沿旧轨迹消散。

注意：

转向形变幅度应当很小。

禁止光球整体被拉扯成不规则的面片。

建议将球壳本体与局部流光分开处理，优先让局部流光承担转向反馈。

## 4.4 动态实现原则

形变只影响视觉，不影响玩家碰撞箱。

使用渲染插值确保动画连续。

不允许因为高帧率或低帧率产生不同的形变速度。

需要对速度变化做适度平滑，防止光球抖动。

# 五、真正的三维流星尾焰

当前需要进一步解决平面 Ribbon 从特殊角度观察时变成细线的问题。

## 5.1 尾焰三维结构

请检查现有尾焰是否主要由面向摄像机的平面 Ribbon 构成。

如果当前结构已经具有稳定的三维体积，不要无意义地重做。

如果存在明显的观察角度问题，请升级为具有三维截面的连续尾焰网格。

推荐采用：

**沿历史轨迹生成变半径的低多边形管状能量网格，并结合少量局部发光光带。**

结构包括：

1. 内部明亮能量核心。
2. 中层较宽的青蓝色主体。
3. 外层少量动态灵气丝线。

### 网格要求

- 截面可使用约 6～10 个顶点起步。
- 沿轨迹平滑变化半径。
- 轨迹弯曲时截面方向连续。
- 不出现明显网格翻转。
- 不出现急转弯时的三角面扭曲。
- 不出现尾焰局部突然变粗。
- 不产生明显的封闭实体管道观感。

可以采用平行运输框架（Parallel Transport Frames）或其他稳定的轨迹局部坐标构造方法。

避免直接使用容易出现翻转的、不稳定的切线叉乘基向量。

如果完全三维管状结构在当前渲染环境下成本过高，可以使用混合结构：

- 低面数三维主体。
- 少量面向摄像机的柔和光带。
- 独立的细灵气流丝。

最终效果必须从侧面、斜后方和正后方观察时都具有足够的可见性。

# 六、尾焰宽度与密度曲线

不要使用简单的等宽尾迹。

沿尾焰的归一化长度 t（0 代表靠近球体，1 代表尾端）定义平滑宽度函数。

目标形态：

- 根部与球体后缘自然融合。
- 前段较宽。
- 中段持续收束。
- 后段加速变细。
- 末端接近零宽度。

建议使用平滑的非线性宽度函数。

不要机械地使用固定线性缩放。

可以使用 Smoothstep、幂函数或经过调试的曲线。

每层尾焰允许使用不同的宽度曲线。

### 内部核心

较窄。

亮度高。

长度可以略短于外层尾焰。

### 中层主体

较宽。

青蓝色。

是远处识别流星形状的主要结构。

### 外层能量

透明度低。

轮廓柔和。

逐渐向外扩散并消散。

不得采用完全不透明的实体圆柱。

---

# 七、尾焰内部能量流动

流星尾焰不应当是一条完全静止的渐变色模型。

需要加入适度的能量流动。

## 7.1 沿轨迹流动的能量纹

在尾焰表面生成少量动态能量纹。

效果：

- 纹理或颜色变化沿尾焰方向运动。
- 速度随玩家飞行速度变化。
- 可以具有轻微波动。
- 不要形成密集条纹。

如果现有系统支持 UV 动画，可以优先使用 UV 偏移实现。

如果没有合适的纹理或 Shader，则可通过顶点颜色及局部流丝近似实现。

不能为了流动效果产生大量新的粒子实体。

## 7.2 能量脉动

尾焰内部可以存在非常轻微的亮度变化。

要求：

- 幅度较小。
- 不出现频繁闪烁。
- 不产生刺眼的亮度跳变。
- 不把整个尾焰做成规律呼吸灯。

建议使用低频、连续变化的函数控制部分能量亮度。

不能让所有尾焰层同时以相同频率大幅闪烁。

## 7.3 局部流丝

保留 3～5 条左右的流丝作为初始方案。

流丝应：

- 贴合尾焰主体。
- 具有轻微空间偏移。
- 具有不同长度。
- 与主尾焰共享轨迹基础。
- 随时间产生柔和变化。
- 在尾部逐渐消失。

不能出现流丝从尾焰中突然分离并朝随机方向飞散的情况。

---

# 八、流星头部与尾焰的融合

这是视觉自然度最重要的部分之一。

目前需要避免球体与尾焰像两个单独的特效。

请实现更自然的衔接。

要求：

1. 尾焰根部位于光球后半部。
2. 根部颜色与光球后缘一致。
3. 根部半径与球体尺寸匹配。
4. 光球后缘亮度向尾焰主体渐变。
5. 不出现明显断口。
6. 不出现明显的圆形切面。
7. 不出现两个特效的透明度叠加造成异常白斑。

可以通过几何重叠、顶点透明度过渡与颜色渐变实现。

在不同相机角度下都要保持自然。

**最终视觉上，尾焰应当像从流星光球自身释放出来的灵气，而不是安装在玩家身后的发光管。**

# 九、转弯轨迹高级优化

请检查现有历史轨迹生成与插值方式。

## 9.1 自然弧线

转向时：

- 流星头部实时跟随玩家。
- 尾焰沿历史移动路径弯曲。
- 旧轨迹缓慢消散。
- 新轨迹连续生成。
- 不允许整条尾焰瞬间跟着人物旋转。

## 9.2 曲率自适应

直线飞行时不需要过多顶点。

转弯时可以适当增加轨迹插值密度。

但必须控制最大细分数量。

应尽量依据曲率、历史点间距和摄像机距离决定网格精度。

不要因为高速移动产生过度细分。

## 9.3 防止断裂

特别处理：

- 玩家瞬间转向。
- 速度骤减。
- 短暂停止。
- 起飞瞬间。
- 传送。
- 切换维度。
- 玩家从服务器重新同步位置。

异常位置跳变必须重置相关历史轨迹，不允许出现跨越地图的巨大尾焰。

# 十、人物与特效的高级联动

保留第一阶段的基础人物动画。

本阶段只做适度精细化，不重新改变动作设计。

## 10.1 高速冲刺

人物：

- 身体接近水平。
- 双臂进一步收紧。
- 双腿并拢。
- 头部朝向前方。

特效：

- 光球轻微拉伸。
- 前缘亮度提高。
- 表面流光加速。
- 尾焰延长。
- 尾部收束更明显。

## 10.2 转向

人物：

- 自动向转弯内侧侧倾。
- 外侧手臂略微展开。
- 内侧手臂略微收紧。

特效：

- 球体主体保持圆润。
- 局部流光响应侧倾。
- 尾焰沿历史轨迹弯曲。
- 后缘能量可以略微滞后。

## 10.3 减速

人物：

- 身体稍微抬起。
- 手臂略微放松。

特效：

- 球体拉伸恢复。
- 尾焰缩短。
- 光球前缘亮度降低。
- 流光逐渐减慢。

## 10.4 突然停止

人物正常恢复原版姿态。

流星头部在短时间内淡出。

历史尾焰按照寿命自然消散。

禁止立即清空所有可见尾迹，除非是死亡、切换维度等需要强制清理的场景。

# 十一、灵气动态的自然变化

我希望流星看起来像由不断流动的灵气构成，而不是静态材质。

请增加适度的非重复性。

允许：

- 轻微的流丝摆动。
- 少量非同步亮度变化。
- 非完全固定的光带形状。
- 少量随机但可控的尾部扰动。

要求：

所有变化应连续、平滑。

不要每一帧重新随机生成所有顶点位置。

如需随机参数，为同一流丝使用稳定的种子或确定性函数。

不能让流星轮廓出现高频抖动。

不能加入大量散乱光点。

---

# 十二、视觉距离分级

考虑到 Minecraft 多人服务器可能有很多玩家同时飞行，请实现合理的视觉复杂度分级。

建议：

### 近距离

展示完整效果：

- 球面流光。
- 多层尾焰。
- 细灵气流丝。
- 精细的颜色变化。

### 中距离

适当简化：

- 保留光球。
- 保留尾焰主体。
- 减少小型流丝。
- 降低轨迹细分。

### 远距离

突出整体轮廓：

- 明确的流星头部。
- 简化的锥形尾焰。
- 关闭不容易被观察到的微小效果。

不要让远处特效突然全部消失。

LOD 切换应尽可能避免明显跳变。

根据当前 Minecraft 版本和渲染框架合理实现，不需要引入大型新系统。

---

# 十三、颜色和亮度的进一步优化

保持整体青蓝色调：

- 内部浅青。
- 核心蓝白。
- 球壳边缘青白。
- 尾焰中层冰蓝。
- 外层流丝偏青蓝。
- 尾部淡蓝并透明消散。

特别注意白天天空。

不要以纯白色作为所有效果的主要颜色。

需要让远处尾焰在浅蓝天空下依然具有明显轮廓。

同时避免夜晚严重过曝。

如果现有渲染管线不支持真正 Bloom，不要假设普通 Alpha 或加法混合能直接产生真实的屏幕空间泛光。

允许通过多层半透明轮廓模拟柔光，但必须控制过度绘制。

# 十四、渲染实现约束

先检查项目当前的 Minecraft、Forge、映射版本和渲染系统。

不要直接套用其他版本的渲染 API。

必须处理：

- RenderType 或版本对应的渲染层。
- 顶点缓冲。
- Alpha 混合。
- 深度测试。
- 深度写入。
- 背面剔除。
- 半透明排序。
- 自发光视觉表现。
- 相机插值。
- 渲染状态恢复。

尤其注意三维尾焰半透明表面可能存在的排序和自身遮挡问题。

优先采用适合当前项目的混合方式。

不能因为尾焰升级成三维网格，就出现明显的深度穿插或透明面排序错误。

# 十六、性能要求

必须保证本阶段的高级效果不会产生明显性能问题。

优先措施：

1. 尽量复用轨迹历史数据。
2. 对连续网格进行批量绘制。
3. 不每帧重新分配大量对象。
4. 避免大量原版粒子。
5. 使用适度的三维截面数量。
6. 对远处玩家减少细节。
7. 尽量复用现有着色器和渲染资源。
8. 不增加没有必要的网络同步。
9. 不引入不必要的全屏后处理。
10. 对所有临时渲染状态正确清理。

如存在明显性能退化，优先保留完整光球和主尾焰，适当减少辅助流光与外层流丝。

**近距离观察：**

能看到流星光球内部的玩家，以及球面上高速流动的灵气。

**高速飞行：**

光球轻微拉伸，灵气加速，尾焰变长，整体具有明显的高速穿梭感。

**转弯飞行：**

人物自然侧倾，光球保持稳定，身后的尾焰沿历史轨迹形成流畅的弧线。

**减速停止：**

光球逐渐恢复圆润并淡出，旧尾焰缓慢消散，玩家平滑恢复正常动作。

最终要求：

整个效果必须像一颗由仙道灵气形成的流星，而不是普通的粒子拖尾，也不是科技激光。
