# 连续流焰本轮验收

本目录只保存 2026-10-09 连续流焰实装后的新证据。工具会读取旧 verifier 的纯 fixture 验证函数（当前 89 张截图、580 项检查、180 张转弯帧、1850 tick），不会读取其旧 RUNS、旧密度扫描或旧球壳结论。

1. 完成生产代码、CPU 回归和 fixture 后，在本目录记录最终 `build runGameTestServer -PrealmFlightOnly` 日志为 `build-and-gametests-final.log`。需要 build、reobfJar、regressionTest、validateResources、specialistChecks 与 7 GameTests 全部成功。
2. 三个运行依次完成后立即保存：`save_flow_run.py native`、`save_flow_run.py oculus-off`、`save_flow_run.py solas`。每次读取实际结果、环境状态与当前源码哈希；失败和旧截图都不能打包。默认保存到 `flow-native-final`、`flow-oculus-off-final`、`flow-solas-final`。新试验可用 `--label` 指定新子目录；禁止覆盖旧证据。
3. 三次运行间不要修改生产源码或 fixture；若修改，全部最终环境证据须重跑。报告、拼图等工具可另行修改。最终三次要求 `bloomDisabledForCapture=false`；额外无 Bloom 诊断可用 `save_flow_run.py native --no-bloom --label flow-native-no-bloom` 保存，不能顶替最终矩阵。
4. 使用 `verify_flow_delivery.py verify` 重新核验。可用 `--native-dir`、`--oculus-off-dir`、`--solas-dir` 更改本轮新标签，不能拿旧目录或三次同环境运行代替矩阵。输出 `delivery-verification.json`。
5. 使用本目录 `make_flow_previews.py <run目录> --no-bloom <无泛光run目录>` 生成六境界原始帧拼图、灰度形态诊断、泛光对照和六段 MP4。只复制、等比缩放与标注实际帧；不绘制新特效。优先查看化神/炼虚/合体同机位直飞、夜间和转弯，再查看其余境界与三管线，检查前端预算、形态差异、旧弯道残辉与衔接。
6. 人工看过当前证据后，运行 `install_flow_verified.ps1`。脚本会再次核验本轮源码、完整证据、最终日志和 JAR，校验主要飞行 class、全部资源、Java 17 目标与测试类未打包；随后分阶段复制到用户授权目录，并把原 JAR 备份到 sibling `mod-backups`。复制后核验两端 SHA-256，输出 `installation-verification.json`。

脚本 PASS 证明证据与当前源码、环境和成品对应，不证明画面审美达标。远端角色经过实际客户端生产渲染，但不是双客户端 LAN 传输验收。不得把预览网页或旧视频拼图作为本轮游戏截图。
