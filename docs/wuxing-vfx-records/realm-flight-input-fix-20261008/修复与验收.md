# 境界御空无法移动：修复与验收

完成日期：2026-10-09。修复已构建并安装到测试 (1) 实例。

## 问题与原因

用户反馈双空格开启御空后，所有方向失效，退出后能走路。只读检查实际保存状态发现：realm=8、flying=true、flySpeed=0、Motion为零，且玩家包围盒下部浸在源水中。详见同目录 user-save-diagnosis.md。

旧控制器把飞行加速度写成零并允许同步、保存。水中会暂停境界控制，旧退出方法又依赖临时 State 存在才恢复速度；读取旧零速状态而没有 State 时，原版飞行的水平与竖直力均为零，也不会切回游泳或重力。

保存快照不能提供反馈瞬间的临时 State，但独立客户端已经按同一条件复现了全向零位移。空气中的普通输入旧版仍能移动，因此没有把空气测试或猜测的按键冲突当作原因。

## 源码修复

- RealmFlightControl：服务端不再留下零飞行速度；没有 State 时同样恢复旧零速；客户端与服务端使用各自的 State 图，避免集成服务器跨线程共享 WeakHashMap。
- RealmFlightMovement：仅在本次受控客户端物理 Tick 内暂停额外原版加速度，PlayerTick.END 恢复；ClientTick.END 对暂停、玩家切换及遗漏 END 兜底。其他模式写入的新非零速度会保留。
- 修复不要求改存档；原先已保存的零速会在运行时恢复。
