# 境界御空：流星形态进一步优化方案

状态：已实施，作为原始设计记录保留。用户后续指出独立多股拖尾与果冻光罩问题，最终交付已调整为单束连续羽流与开放辉光。最终实现、实际游戏验证和安装记录见同目录《最终交付与实机验收.md》。本文中的三至五股独立尾焰参数已被后续反馈替代。

## 1. 本轮要解决的画面问题

实际游戏截图已经暴露出三个问题：

- 头部有完整、规则的椭圆边界，容易被看成护罩或气泡。表面细丝过密，进一步强调了网状球壳。
- 尾部主要由一根很亮的细芯承担视觉重量。外层烟纱较弱，最终仍然像一条线；加大泛光会得到更亮的线，无法改变形态。
- 头部与尾部各自成立，缺少从玩家肩背、腰侧向后汇流的连接区域。整团能量没有共同的运动方向。

这次以轮廓、密度和流向为核心重做。目标是让玩家处于一团向后喷流的青白气焰中，后方展开有厚度、有分股、有消散的尾焰。靠近能看到身体与装备；远处首先读到划过天空的流星。

## 2. 画面构成与视觉权重

整体按“明亮前部 → 包裹人物的气焰 → 宽尾根 → 分股尾焰 → 稀疏消散”连续过渡。

| 区域 | 要形成的轮廓 | 主要颜色 | 视觉处理 |
|---|---|---|---|
| 前部 | 前方略圆、向两侧掀开的短亮弧 | 青白 | 两三段断续弧，避免闭合成完整圆环 |
| 人物周围 | 前紧后松、边缘不规则的气焰 | 白青与浅蓝 | 中央留透视空间，亮丝集中在肩侧、腿侧与外沿 |
| 尾根 | 从人物后方张开的宽羽流 | 明青色 | 接入肩背、腰侧和脚后，避免细线接在球心 |
| 主尾 | 三至五股相互靠拢又分离的流带 | 白青、青蓝 | 粗细、长度与相位错开，沿真实飞行路径弯曲 |
| 外尾 | 断续薄纱、少量脱落的光屑 | 低饱和蓝 | 逐渐散开、变薄、消失，尾端不形成整齐尖线 |

鬼仙沿用同一结构，白青改为白紫，维持亮芯与外层的层次关系。

## 3. 头部：去掉完整椭圆护罩

### 3.1 形态

头部改为沿速度方向展开的气团：前端收紧，后端与宽尾根重叠。三维载体仍用于限定绘制区域，实际可见边界由程序密度决定，不再通过整圈 Fresnel 描边呈现一个封闭椭圆。

- 前侧保留短而亮的冲开气流形状，偏向飞行前方。
- 两侧出现较宽的卷曲薄层，朝人物后方回卷。
- 后侧逐渐打开，与尾根共用密度过渡，不能出现“完整球壳后面另接尾巴”的接缝。
- 对称性稍微打破：左右两股流动不同相位，上下亮度不同，但整体重心稳定。

### 3.2 材质

采用两级三维场：低频密度负责大尺度气焰；高频侵蚀与卷曲细丝负责局部运动。先保证大形，再加细节。

- 低频密度形成两三块连贯的宽亮面，避免整壳只有细线。
- 细丝覆盖率明显减少；细丝方向以由前向后流动为主，避免均匀交叉成网格。
- Fresnel 仅调节局部边缘，不承担完整外轮廓。
- 面向人物的中心区域降低密度；身体与盔甲不会因一层高亮泛光整体消失。
- 亮度主要集中在前弧、外侧汇流和尾根。泛光用于扩散这些亮区。

近距离气团部分拟采用包围体中的三维密度积分。借鉴 minecraft-energy-vfx 的气团、烟纱与侵蚀方法，专门适配本项目的玩家状态和渲染通道；不直接安装其独立运行库，也不继承该技能的兼容结论。

## 4. 尾部：把单根细芯改成分股尾焰

### 4.1 宽度变化

尾焰在人物后方先展开，再逐渐收束。拟定起点：

| 参数 | 巡航 | 疾行 |
|---|---:|---:|
| 人物周围气团总宽 | 1.9～2.3 格 | 2.2～2.7 格 |
| 宽尾根总宽 | 1.8～2.4 格 | 2.4～3.2 格 |
| 尾焰中段总宽 | 0.9～1.5 格 | 1.3～2.1 格 |
| 明显可见的整体尾长 | 12～18 格 | 24～36 格 |
| 主流带数量 | 3 股 | 5 股 |
| 外层烟纱宽度 | 主流带包络的 1.4～1.8 倍 | 主流带包络的 1.6～2 倍 |

这些是调试起点，最终以游戏截图判断。低境界速度较慢时，尾长由实际经过的距离自然缩短，不能凭空把尾巴拉直到设定长度。

### 4.2 三类可见结构

1. **主流带**：较宽、柔边、长度错开。每股有独立的偏移、局部弯曲和脉冲，避免平行直线。白色亮区主要位于各股内部的断续波峰。
2. **卷曲烟纱**：在主流带外侧形成少量宽而薄的卷曲层。遮罩侵蚀出空隙，使尾焰有空气感，而不是实心圆柱或一整张光片。
3. **光屑**：少量短寿命亮点脱离外层，继承一部分飞行速度后衰减。占次要视觉重量，不能依赖大量粒子来替代主尾焰。

中央连续白线取消独立主导地位。确有必要保留时，其亮度和长度应低于两侧主流带，避免再次把整条尾焰压成一根线。

### 4.3 真实轨迹与时间

- 20 Hz 保存世界空间历史，记录最多 48 个样点，覆盖约 2.4 秒移动。
- 飞行中，旧位置保留在世界里。转弯会留下弯曲尾焰；新流带不能把旧尾焰一起旋转。
- 使用稳定的截面方向和平滑曲线，沿曲线重新计算弧长，流纹沿弧长连续移动。
- 渲染头部使用与人物相同的插值时刻，移除当前渲染时刻之后的历史样点，防止尾根折返。
- 停止或退出时停止产生新尾焰，已有尾焰额外乘一个 0.6～0.9 秒的整体淡出包络。因此记录较长历史也不会造成退出后长期残留。
- 传送、切换维度和退出观察范围时断开轨迹，禁止生成跨地图的连线。

## 5. 头尾衔接

衔接区域占人物后方约 2～3 格，是这次形态修改的重点。

- 气团后侧的两股卷曲薄层，直接进入主尾的两条侧流。
- 中间一股从腰背向后汇入，脚后提供较细的下侧流。
- 头部后侧密度与尾根前侧密度使用重叠渐变，亮度不会在接缝处突然增大。
- 统一头部、尾根与尾部的时间、主流向及噪声相位，避免各部分各自旋转。
- 尾根在启动时展开，尾部随着真实移动逐步长出。停止时尾根先收弱，旧尾部继续消散。

## 6. 动作与不同观察距离

| 状态 | 人物与气焰 | 尾部行为 |
|---|---|---|
| 悬停 | 人物直立，周围两三股缓慢回卷的青色气焰 | 没有长尾，后侧只留轻微逸散 |
| 开始移动 | 人物平滑进入横飞，前部亮弧增强 | 尾根在约 0.2～0.35 秒展开 |
| 稳定巡航 | 气焰形状稳定，内部流动持续 | 三股宽尾焰，外层断续薄纱 |
| 疾行 | 气焰沿前后方向拉长，亮区更集中 | 五股流带，尾长和展开幅度增加 |
| 急转 | 人物倾斜，头部对齐实际速度 | 旧尾留在原轨迹，新尾形成连续弯折 |
| 停止/退出 | 恢复普通姿态，周围气焰迅速减弱 | 停发后 0.6～0.9 秒消散 |

距离约 4～12 格时，能辨认人物与流层；24～48 格时，先读到完整气焰和宽尾；64～100 格时，简化成亮头与有展开、收尾的流星轮廓。远处不能因削减所有外层而重新只剩一个亮点和细线。

第一人称继续隐藏自身覆盖视野的气团与尾焰，保留正常操作视野。其他玩家看到完整效果。

## 7. 源码与渲染接入方案

| 模块 | 拟改动 |
|---|---|
| RealmFlightEffects | 拆分轨迹采样、形态生成和绘制；增加连续尾根与分股路径，按观察距离选择细节 |
| 新的路径辅助类 | 处理渲染时刻裁剪、平滑、实际弧长、截面连续性、停止淡出和传送断开 |
| 新的气团材质 | 从三维密度生成宽气焰、卷曲烟纱和局部亮丝；采用稳定世界时间与 UUID 种子 |
| realm_meteor 着色器 | 重做主流带密度和遮罩；白芯从连续轴线改成分股、断续亮区 |
| MeteorBloomRenderer | 保留独立 emission 与深度约束；分别调整气团、流带和光屑的发光贡献 |
| RealmFlightVisuals | 维持慢速境界也能进入横飞，动作保持平滑，保留正常使用物品与攻击动作 |

复用当前着色器注册、御剑深度桥、资源回收和多人视觉状态同步。飞行资格、移动速度、灵力消耗和碰撞功能不因外观设计改变。

近距体积采样与尾部流带采用不同预算：近处气团提供厚度，长尾主要由三维路径上的薄层与流带承担，避免沿整条长尾进行高成本体积积分。

## 8. 性能与兼容验证

- 第一阶段限定单个近距离玩家，体积采样拟从 16～24 步调试，确认轮廓与内部运动；该数值属于新的专用实现，不直接套用技能配方中的 steps。
- 第二阶段加入多玩家预算：优先本地第三人称与最近的可见玩家，远处减少积分和股数，同时保留尾焰宽度。
- 总容量满时优先淘汰远处或已停止状态，不能把新出现的近处玩家永久拒绝。
- emission 共用缓冲并统一模糊，按效果覆盖区域限制体积绘制，禁止逐玩家复制全屏和模糊。
- 几何、体积、Bloom 分别计时，比较关闭效果、1 名、4 名和多人御空；性能目标需在实际机器上测得。
- 真实测试普通渲染和 Oculus + 用户 Solas 包。特别检查逆光、夕阳、夜间、透明水面以及前景方块遮挡。
- 当前已验证的普通渲染、模拟后置通道，不等同于 Solas 实测通过。此次隔离 Solas 运行因系统内存不足终止，后续需重新完成实机兼容验收。

## 9. 分阶段实施

**第一步：确认形态。** 先停用细丝和 Bloom，只绘制头部密度、宽尾根与三股尾焰。游戏里分别看侧面、后方、斜前方和 48 格观察位置。此时应该已经能读成流星。

**第二步：加入运动。** 添加从前向后的卷曲流动、分股脉冲、外层侵蚀和停止淡出。检查转弯是否保留历史路径，尾根是否与人物连续。

**第三步：加入发光。** 分别调整白青亮区、蓝色薄纱和光屑的 emission，最后调 Bloom。需要避免依靠提高曝光掩盖形态问题。

**第四步：游戏验收。** 完成各距离、动作、遮挡和光影测试；保存实际截图及短序列，再构建生产 JAR。视觉未达到下方标准时继续修改，不将“构建成功”写成完成。

## 10. 验收标准

1. 侧面轮廓从亮头连续过渡到宽尾根和渐细尾焰，没有闭合椭圆圈与单根线的拼接感。
2. 暂时关闭 Bloom 后，仍能辨认三股以上有宽度变化的尾焰；打开后层次仍存在。
3. 近距离能看清人物头部、躯干和装备轮廓，白色过曝区集中在气焰亮部。
4. 头部大尺度流动明显，表面没有覆盖整个气团的均匀网格。
5. 急转、上升和下降时，头部随速度转向，尾部保持真实弯曲轨迹，没有尾根折返和截面翻转。
6. 64～100 格观察时，仍然读到划过天空的流星轮廓；缩减细节不会退化成亮点与细线。
7. 停止后尾焰按预定时间消散；传送、离开世界和资源重载没有长连线或残留。
8. 在真实 Solas 环境取得同类截图，确认特效可见、遮挡正确，人物和 UI 不受错误状态污染。

最终交付应包括生产 JAR、安装文件校验、完整源码，以及巡航、疾行、急转、远距观察和停止的游戏内证据。概念预览、渲染计数和 GLSL 编译结果单独标注。
