# 程序流星御空待审方案

本轮仅设计，不修改游戏源码、不构建、不安装。

## 已确认的问题

realmFlightAnimation默认值仍为true，但上一版RealmFlightVisuals.excluded新增了RealmFlightEffects.transformed，导致特殊飞行时退出原有姿态控制，人物因此呈现原版姿态。这是入口冲突，不应通过重置用户设置修复。

上一版使用踏罡图集的柔光格和白色格绘制外壳、光带，没有专门的能量流动材质算法。截图中的均匀直条正是缺乏横截面渐变、流动和边缘衰减的表现。御剑已有sword_trail_post绘制桥及场景深度遮挡，可复用通道；该片元着色器本身主要负责颜色和深度，不等于参考图所需的全部能量算法。

## 视觉目标

采用第二张参考的青白流星：近处看清玩家，周围是流动的椭球气罩；中距离看见明亮头部和汇聚长尾；远处合并成划过天空的流星。保留身体、装备和手。不得以第二张概念参考的Bloom、云层和夕阳反推游戏已能呈现同等画质。

悬停时身体直立、光壳较圆、弱流动，不保留长尾。移动时恢复原来的速度驱动横飞与转弯倾斜，光壳沿实际速度方向拉长；疾行时头部更亮、流丝更快、尾部更长。退出飞行后立即恢复普通人物，尾迹0.6～0.9秒内消散。

## 主体材质

使用真实三维椭球网格包裹玩家，宽约1.8～2.2格、纵长约2.4～3格；前端圆润，后端与尾迹自然收束。视角相关边缘亮、低透明度内部、三层沿流向运动的程序细丝共同构成气罩。白青主色，亮芯偏白、外缘偏蓝；鬼仙使用白紫同一结构。

GLSL通过局部坐标、法线、视向、时间和速度绘制Fresnel边缘、流向噪声、断续细丝和能量脉冲。光壳前端的亮弧侧面更明显，观察者近处仍能看到人物，不能变成不透明白球。

## 拖尾材质与几何

20Hz保存真实位置历史，插值生成平滑带或多截面管；主白芯、青色流带、蓝色薄纱三层独立宽度。中心线随转弯弯曲，连接处保持连续，避免折段、矩形边和整条恒定宽度。

每个顶点提供累计弧长、横向坐标、年龄、层编号。片元着色器按横向距离产生柔边与白芯，按累计弧长和时间形成流动条纹；沿尾部收窄、年龄淡出，侧翼叠加少量程序螺旋细丝。无需图集或卷轴式滚动贴图充当拖尾。白芯不能一整条硬截面白矩形。

目标长度：巡航约8～14格，疾行约16～24格；转弯和低速按实际路径缩短。寿命0.6～0.9秒，几何限制48点、每人约6千顶点；32格以外减少细丝，64格外仅保留头部和主尾，128格外进一步减少截面，仍保留可辨认的流星轮廓。

## 接入与兼容

修复姿态入口冲突；特殊御空默认启用，同时尊重用户主动选择的原版模式。飞行资格、速度、消耗及碰撞逻辑不变。

扩展御剑已有的TrailShaderBridge，注册专用realm_meteor和realm_meteor_post程序材质。复用其光影检测、场景深度、后置提交和状态恢复，保留其他御剑/踏罡着色器。常规和光影通道使用相同能量函数，光影通道另做逐像素深度遮挡。

材质柔光和真实屏幕Bloom分开验收：基础版在原版环境也应明显；额外Bloom如需加入必须拥有独立发光缓冲、深度遮挡和资源回收，不把一个白贴图或简单加色说成Bloom。第一人称不在视野中心覆盖本体气罩，第三人称和其他观察者绘制完整效果。

## 实装顺序与验收

先恢复特殊姿态并制作主体、连续尾部的程序着色器预览；确认白芯、柔边、流丝和人物可见度后接入游戏。再分别验证悬停、巡航、疾行、急转、停下、落地、传送、远处观察；检查原版与用户实际光影包下的深度遮挡和亮度。构建通过不能代替游戏内看图。

本方案确定前不覆盖测试实例JAR。
