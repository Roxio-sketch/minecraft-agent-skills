## 针对当前画面的改造依据

连续主体应先有完整截面与纵向连通性。宏观起伏、水片、泡沫再附着到主体，不能用稀疏角向遮罩切穿整柱。多层不规则水片与飞溅保留，但大孔洞主要位于外围薄片及顶部剥离区域。

Particles4All 的压缩约束不会凭空给稀疏区补水，屏幕空间过滤也会直接跳过空深度。它们不能代替连续占据分布。要先控制载体/粒子的覆盖，再调整重建核与滤波。

螺旋感同时来自大形和流动。建议让中心线、半径、螺旋节距与旋向共用一组定义；粗水纹、高光/泡沫跟随这一局部坐标，细法线允许速度差。圆柱周向需要周期接缝处理，双相位混合不能自动解决 angle wrap。此处是根据源码提出的设计推导，尚未实现或验收。

下一轮先比较两条路线：现有平台可做的连续 SDF/网格主体加水片；以及粒子模拟配合屏幕空间或网格表面重建。前者便于控制造型，后者能研究断裂与合并，但引入状态、邻域搜索、密度约束和更多渲染通道。不会把程序噪声移动写成已实现的流体对流。

## 推荐的下一轮验证

1. 固定相机，分别显示主体、螺旋大形、水纹、泡沫和飞溅，观察每一层是否解决对应问题。
2. 检查底/中/高截面、侧面与旋转观察时的连通性；关闭细节仍应有完整主形。
3. 检查周向接缝、旋向、节距和沿螺旋上升的轨迹；暂停/回放使用固定世界时间。
4. 对水柱曲面记录入/出水距离与厚度，检查遮挡和前景折射；海面平面反射独立处理。
5. 进入实际 Minecraft 接入前，再验证深度、FBO/GL 状态恢复、透明层顺序和其他特效合成。本包没有游戏兼容性或性能验收结果。
